2026-10-13，针对用户要求调整模型产物上限。本次不调用 LLM、不运行完整 Benchmark、不读取外层测试标签；原真实验收失败记录保持原样。

## 新建模默认值

| 配置字段 | 原默认 | 新默认 | 原因 |
| --- | ---: | ---: | --- |
| `max_artifact_bytes` | 16 MiB | **256 MiB** | 覆盖实测 174 MiB 模型，并留出约 47% 余量 |
| `max_artifacts_bytes` | 64 MiB | **1 GiB / 执行会话** | 执行结束与关闭各收集一次快照，二者均计费，还要容纳元数据及其他文件 |
| `workspace_bytes` | 256 MiB | **512 MiB** | 给模型文件、临时产物和余量留空间 |
| `memory_bytes` | 2 GiB | **4 GiB** | 同时考虑拟合对象、tmpfs 文件及整帧 base64/JSON 的多份内存表示；这是上限，不是固定预占 |
| `max_frame_bytes` | 1 MiB | **按单产物推导，约 341.40 MiB** | `max(1 MiB, 4*ceil(max_artifact_bytes/3)+64 KiB)` |
| `interrupt_grace_ms` | 3 秒 | **15 秒** | 当前也用于关闭时收集产物，174 MiB 的清理快照实测超过 3 秒 |

建模模型在初始任务中收到有效内存、工作区、单产物及累计产物限制，可据此约束模型复杂度。普通终端输出的 `max_output_bytes` 仍为 8 MiB；16 MiB 的原故障针对 `model.joblib`，不是打印输出。

`limits` 可按开发资源和任务覆盖默认值，例如只设置 `max_artifact_bytes` 会自动推导相应帧额度；显式 `max_frame_bytes` 被保留，包括旧运行中冻结的值。增加单产物额度时还应同步考虑累计快照、工作区和内存。本轮没有修改第一章独立 EDA 的全局默认资源。建模委派的 EDA 按既有机制继承本次建模执行限制。

这是当前受控开发配置，不能据此声称全部 52+51 个基准任务都适用或已经通过。完整基准预算尚未冻结；大型数据和更复杂集成需要成本预实验及显式配置，现有建模数据适配本身也有独立的大小和任务类型边界。比较方法/消融时必须使用同一明确资源档位。

## 配套修复与验证

提高文件上限还暴露出三个实际传输问题，均已处理：

1. 原 1 MiB JSON 帧装不下大型模型的 base64，改为按产物额度推导。
2. 协议和宿主持久化的重复分组正则会拒绝大型合法 base64，改为共享的线性字符/长度/填充校验，保留原合法格式。
3. 管道每收到一个分片就复制整段未完成帧，改为有界累计分片、收到完整行后只拼接一次，仍拒绝超限和截断帧。

首次无 LLM 完整传输验证已成功保存 174.091 MiB 模型，但关闭时二次快照超过原 3 秒宽限，运行明确失败。该诊断记录保留于 `runs/modeling-resource-probe/10264aad-81dd-4d80-bbf3-465600d956d6`。随后修正清理宽限与累计额度，重新执行同一代码的完整拟合/独立预测，通过：

- 成功记录：`runs/modeling-resource-probe/a9fd3829-8832-4867-a796-03ef59accf66/validation.json`。
- 模型 **182,548,159 字节**，保存、关闭收集及独立预测容器加载均完成。
- 预测文件 25,051 字节；只检查输出格式与样本身份，没有读取测试标签或计算外层分数。
- 总墙钟约 **25.36 秒**，0 次 LLM 调用。此为开发验证，源码工作区当时含当前修复，原生阶段清单如实记录 `dirty:true`，不作为正式实验。
- `bun run check` 通过：192 个 TypeScript 测试、1,259 个断言，34 个 Python 测试。新增覆盖大于 16 MiB 的有效产物、非法 base64、碎片帧/超限/截断、动态额度及旧显式配置。

另有真实 Docker 树集成回归用例，验证大于旧上限的模型经过两次快照后仍可在新容器中预测，并保持较小显式上限的拒绝行为。全量 `bun run test:integration` 通过：28 个 TypeScript 测试、309 个断言（307.14 秒），6 个 Python 集成测试（12.28 秒）。`openspec validate add-modeling-candidate-budget-control --strict` 通过。

此次容量修复没有解决原 EDA 的非法证据引用和 token 预检问题，也没有再次调用真实建模智能体。`docs/modeling-candidate-budget-validation.md` 中的首次真实验收仍然失败，任务 5.5 继续未完成。
