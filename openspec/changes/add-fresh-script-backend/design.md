# Design

## Context

动机见 [proposal.md](proposal.md)。本变更跨越执行协议、角色提示、记录与评测，涉及进程生命周期及旧记录兼容，因此需要设计文档。

当前 `src/agent/run.ts` 已通过 `AgentSession` 隔离 execute/cancel/close，但执行返回、会话连续性提示和终止判断仍使用 `cell_id`、`kernel_epoch`、`kernel_available`。`DockerSession` 与 Python bridge 均围绕持久 Jupyter 内核运作。`src/records/replay.ts` 从 Notebook 视图重放，`trajectory.ts` 从单元事件构造轨迹；这些地方不能直接用于独立脚本。

运行时已提供 Docker 非 root、无网络、只读根文件系统、输入白名单及受限 tmpfs。镜像入口与内核启动均经 uv，已有 numpy/pandas/matplotlib/IPython 相关依赖可复用。现有模型接口一次提交代码即执行，没有文件编辑或 Notebook 单元修改工具。

主规格的 `execution-session` 和 `eda-agent` 有无条件的持久内核描述，本变更以对应增量区分后端；`notebook-execution` 继续专门约束持久 Notebook，不将其语义改成脚本。旧记录、模型建模流程和持久提示词是兼容性约束。

## Goals / Non-Goals

**Goals:**

- 将“角色组织”和“执行后端”作为独立配置维度，共用决策、预算、证据和报告流程。
- 只移除脚本组的进程内状态及增量执行便利，保留任务记忆、文件访问范围和必要反馈能力。
- 以运行时约束和 Docker 测试证明进程隔离及清理，不靠提示词宣称状态已清空。
- 完整保存尝试、失败及启动开销，并能按原后端重执行。

**Non-Goals:**

- 不开发 Notebook 编辑器、单元更新/删除/指定重跑、变量浏览器或自动代码补全。
- 不增加图像模型输入、持久后端新功能、独立调试角色或跨任务缓存。
- 不把四组开发配置当作正式实验冻结，不实现纯 LLM、外部研究基线或建模消融。

## Decisions

### 1. 显式后端配置，保留既有持久路径

在 EDA task 和 Statigent adapter options 中增加 `backend: persistent-kernel | fresh-script`，缺省为前者。执行配置记录实际值；直接 runtime 入口也能显式选择脚本以支持无模型验收。角色组织保持原枚举。现有建模调用不传新选项，继续持久后端。

通过受信会话工厂选择执行实现，提取共享的输入发布、容器限制、产物校验等能力，保留持久 bridge 的执行行为、旧协议和现有提示词字节。不要复制整个 EDA run 循环或在多个调用点自行猜测后端。

另一方案是用 Notebook restart 模拟脚本；不采用，因为它仍是内核单元执行，影响初始化、输出和重放语义，也容易被解释为原内核的恢复。

### 2. 任务级容器，调用级 Python 进程

新增固定脚本 bridge 与 runner，容器每任务一个，任务内保留 `/workspace`；bridge 不执行生成代码，只管理新的子进程、输出、产物和生命周期。每次子进程使用冻结环境的 `uv run --offline --no-sync --project /opt/runtime python ...` 启动，禁止临时安装或下载。Docker 入口选择只能由可信后端配置决定，不接受模型传入任意宿主命令。

每次提交保存独立脚本快照，在新解释器中按普通 Python 脚本语义执行，当前目录为 `/workspace`。不拼接历史代码，不加载历史 globals，不自动读取缓存。runner 只负责初始化、输出捕获和异常封装，初始化内容及版本进入记录；用户脚本本身保持原样。控制器临时源码使用独立受限目录，不作为默认任务文件产物重复收集。

保留任务内文件意味着模型可以显式保存并读取清洗数据等缓存，文件不是自动恢复的对象。每次执行的 cwd、环境与随机源重新初始化；文件修改不会因异常回滚。跨任务工作目录为空，宿主记录区不可写入或作为脚本输入。

每次启动新容器也能隔离内存，但需要重新发布中间文件并带来额外 Docker 启动成本；本方案选择每任务容器，以保留文件自然语义并控制与核心消融无关的开销。

### 3. 进程树清理是下一轮执行的前提

单会话仍串行执行并拒绝重复请求。每次脚本使用独立进程组，关闭交互 stdin。普通完成也要终止并回收残留子进程；SIGINT/TERM 后有界升级终止，必要时删除整任务容器。

仅等待主进程或 kill 进程组不足以覆盖自行脱离的进程。运行器须采用子进程回收及容器内进程清点，识别本轮留下的后代，包括重新建立 session 的子进程；无法确认容器回到仅受信运行器活动的状态就终止会话，绝不带着后台计算进入下一轮。清理确认前不收取“最终稳定快照”或发布下一请求。迟到输出关联原请求或作为诊断，不串入下一轮。

Python 子进程不是安全沙箱，隔离仍依赖既有 Docker 限制；运行器也不能将同用户的生成代码当可信协议端。生成代码导致 bridge 退出或协议无法确认时明确失败，不承诺自动修复。

### 4. 协议按后端判别，避免伪造内核事实

持久 bridge 保留 v1 wire protocol。新增脚本 wire protocol v2，握手必须匹配后端和版本；配置了脚本但镜像不支持时，在调用模型前拒绝。宿主对请求、响应、身份、输出大小和版本均运行时校验。

计划预览仍不启动容器：只解析配置及镜像声明的后端能力，实际运行预检在首个模型请求前完成受限 bridge 握手。旧镜像未声明脚本能力时只允许原持久路径；不得为预览能力而偷偷启动执行任务。

脚本请求/结果使用 `execution_id`、`request_id`、`session_id`、`execution_seq` 及唯一进程实例身份；PID 只作补充，因为 PID 可复用。结果包含 started、状态、会话可用性、内存不保留、文件保留策略、完整度和阶段耗时。未成功启动的尝试不能编造 PID 或已执行状态。

EDA 边界使用带后端判别的公共执行视图，把原持久 `cell_id` 映射为通用执行引用而不改变其原值；持久特有 epoch/可用性原样保留，脚本不填假的 kernel epoch。成功证据、角色 journal、报告与产物来源通过该边界接入。`kernel_available` 的旧终止判断改为后端对应的会话可用性，脚本成功退出不会触发 execution_state_unavailable。

脚本 stdout/stderr 与 bridge 控制流分开捕获；原样打印的 JSON 只能成为输出，不能成为控制结果。富输出通道仍按不可信数据校验类型和大小，只有运行器确认的结束、退出状态、清理和完整协议共同构成终态。提前退出或缺失必要结果不默认成功。

### 5. 保持必要反馈能力，明确脚本表达式差异

新 runner 捕获 stdout/stderr、异常及显式静态 display 的文本/HTML/PNG，复用已有产物收集与限制。优先用现有 IPython 显示机制安装受限的显式 display 输出钩子，不运行持久 InteractiveShell，不使用共享用户命名空间，也不新增依赖框架。图片仍只向模型提供引用和文本，文件图表支持 `savefig`，报告沿用既有文件/规划者交付规则。

脚本不隐式展示末尾表达式，不支持 Notebook magic、跨执行 display update 或交互输入；提示说明使用 print、显式 display 和保存文件。这些输出语法差异需要记录为比较限制，不能把缺少自动回显造成的空反馈当作没有计算。测试须证明表格和图表仍可产生等价的必要信息。

### 6. 角色上下文共用，后端指令独立版本化

沿用 `execute_python(code)` 单次工具粒度，脚本模式只更换工具描述、初始化消息和后端相关指令。持久模式继续使用现有 prompt 版本及原文，不对它顺便优化。

脚本模式保留执行者历史代码、反馈和证据，规划者仍只接收结构化返回。双角色后续委派的 execution_context 区分“任务/工作目录连续”与“内存不连续”，不能沿用含义不明的 session_continues=true 让模型误以为变量仍在。移除脚本提示中“直接接续内存变量”及“文件不能用于状态交接”的持久专用指导，明确完整脚本和显式文件复用。

普通错误继续使用既有有界修复和动作纠正次数；调用失败、未知用量、取消和全局时限保持既有终止语义。新进程、委派切换都不重置次数、token、累计输出或产物额度。

### 7. 记录与导出按后端选择

为新执行记录引入 manifest schema v4，包含必需且版本化的 execution 信息：后端、文件策略 `task-workspace`、初始化/种子规则和导出类型。v1/v2/v3 只读按原持久语义解释，不写回补字段。新格式缺少字段或未知版本直接拒绝；共享记录写入升级不能破坏建模子运行、角色 journal 或旧镜像重放。

持久运行继续导出原 Notebook；脚本运行导出 `scripts/<sequence>-<execution_id>.py` 和有哈希的执行清单，输出/错误仍由现有事件和产物索引关联，Notebook 状态为 not_applicable。脚本顺序、源码、初始化版本及返回终态必须可审计。任何修改/失败尝试均保留，宿主快照不受同名工作文件覆盖影响。

单次耗时分列进程初始化、用户执行、收集及清理，总墙钟包含这些开销但不与之再次相加。保留容器启动耗时；持久端已有启动、执行与清理口径保持原解释，不为它增加运行行为。

### 8. 重放保留实际进程边界

将重放调度从“遍历 Notebook”扩展为按记录后端选择：持久走旧资格与执行路径；脚本走实际脚本清单，从新容器与空工作目录按顺序启动新进程。文件复用由重放中的前序脚本重新生成，不拷贝原工作文件。校验原镜像、平台、输入、源码与初始化版本；原记录逐字节不变。

沿用严格资格：含错误、未知结果、保存不完整、未完成任务的轨迹报告 unsupported，不为通过而删失败脚本。正常脚本多进程不是内核多 epoch 错误。passed 只证明代码按原后端重执行成功，不证明数字/图像逐字节一致，更不代表 LLM 决策或规划者报告被复现。无需模型服务。

### 9. 开发对照配置与验收分层

基于现有 InfiAgent、DSBench-Analysis、DAComp-DA 的固定 development-selection，新建各基准独立的 `*-backend-ablation-development.json`，每个计划配置四组，不改旧配置。使用同一构建镜像和模型 profile；同一基准内各组统一逐题模型、执行、修复、token 和时间预算。执行顺序、重复次数及种子记录；整批预算按四组计划显式计算，并保留预览及预算缩减标记。评分协议和评委配置保持基准原约定，费用单列。

配置准备可复用现有开发任务选择，但不声称原预算已适合四组公平性能比较。实际预实验后可产生新版本预算配置；正式评测需另行冻结任务与预算，不按测试成绩选题。本变更只交付可运行入口、配置和无模型验收。

真实脚本冒烟提供单独入口，显式选 single 或 planner-executor，默认不自动运行两项。沿用合成输入并冻结目标：计算、显式保存中间 CSV、后续独立脚本读取、图表与报告交付；验证本轮进程身份及后端、不要求性能改善。启动前可做无模型 preflight；真实调用需后续明确任务与预算，不将其作为当前规划或默认 check 的副作用。

### 10. 种子与成本解释

每轮新脚本使用同一任务种子初始化 Python random 与 numpy，与持久内核首次初始化使用相同规则；记录脚本模式的每轮重置事实。持久随机流跨轮延续，新进程随机流不延续，这是状态差异的一部分；不额外让宿主传递 RNG 状态。相同脚本的重新执行在相同环境和种子下可核验，第三方库自行生成的随机性须由模型在代码中显式设置。

允许磁盘复用后，实际轨迹可能以文件弥补内存缺失。比较应报告该允许策略，不能声称每轮必然从原始输入重算；本轮不构建自动语义缓存识别器或因果收益判定器。

## Risks / Trade-offs

- [后台进程保留状态或产生迟到写入] → 将进程清点和回收列为完成门槛，覆盖脱离进程组的测试，不能确认则终止整个任务容器。
- [新格式影响旧 Notebook 和建模] → 保留 v1 bridge，v1–v3 只读兼容；针对旧目录哈希不变、原镜像重放和建模集成做回归。
- [独立进程反复导入增加耗时] → 启动开销计入任务墙钟并分列；不通过提前导入到常驻用户解释器隐藏成本。
- [文件复用弱化组间差异] → 固定为已确认的对照条件并披露，不在运行后依据结果临时禁用。
- [输出语法差异影响模型表现] → 提供同等必要输出渠道，后端提示明确脚本语义，并在预实验轨迹分析中区分反馈问题与状态问题。
- [普通异常留下部分文件] → 不自动回滚；保留错误、快照和诊断，模型在有限预算内自行核对与修复。
- [四组增加模型及评委成本] → 新配置显式预算、只读预览；本变更不自动派发真实批次。

## Migration Plan

1. 在任务分支按协议/执行、记录/重放、EDA/评测几个内聚阶段实现并经检查后提交。
2. 构建同时支持两后端的新开发镜像，保留旧镜像身份以复现旧运行；不把 mutable tag 当作历史镜像身份。
3. 先完成合成可控模型与 Docker 验收，再提供冻结真实冒烟配置及 preflight。实际真实验收的通过/未执行状态分开记录。
4. 同步使用文档及研究文档中任务内文件复用口径，保留历史验收记录和旧配置。
5. 回退时将新任务 backend 设回 persistent-kernel 即可继续原流程；已经产生的新脚本记录仍须由支持 v4 的只读工具查看，不原地降级或改写。
