# Proposal

## Why

现有 EDA 已有单智能体循环、持久 Notebook 和三套分析基准接入，但尚未实现第一章确定的规划—执行分离。先补齐这一核心协作链路，形成可独立调用的完整 EDA 能力，再接入第二章建模协作；本次以功能可用与可追溯为验收目标，不提前声称研究收益。

## What Changes

- 新增可显式选择的规划—执行分离模式，保留现有单智能体模式及其默认行为，两种模式共用模型调用、预算、执行和记录基础。
- 规划者委派明确的分析问题，根据结果继续委派或完成；执行者自主开展多步计算、必要检查与有界修复，跨委派复用同一个持久内核和执行者上下文。
- 通过版本化角色提示词引导适中粒度：问题明确、求解自主、新的分析方向返回规划者。程序校验结构、证据、权限和预算，不判断问题语义粒度，不新增粒度控制模型。
- 建立独立角色上下文与结构化子任务结果，规划者接收结果、统计口径、证据和必要诊断，不直接接收完整代码、原始执行输出或逐次调试轨迹。
- 统一全任务预算与取消，记录角色及子任务成本、委派关系和执行证据。最终结论由规划者提交，支持现有文本及带图片报告交付。
- 接入现有 EDA CLI 与评测适配器，显式传递执行次数等原生预算；提供合成集成验收与有界真实模型冒烟入口。
- 本次不实现第二章建模、每轮新脚本后端、粒度优化/自适应调度、上下文压缩、额外 Debugger、智能体视觉或正式对比/消融实验。

## Capabilities

### New Capabilities

无；在已有 EDA、运行记录和智能体适配能力中扩展职责明确的协作行为。

### Modified Capabilities

- `eda-agent`：增加角色组织配置、委派与结果返回、上下文边界和全局预算；扩展完成与报告交付，使规划者负责双角色模式的最终结果。
- `execution-records`：记录双角色模型身份、提示词、用量和子任务关系，支持既有记录读取、导出与重放。
- `agent-adapters`：允许显式选择双角色 EDA、透传原生预算配置，记录角色组织与多角色到统一轨迹的映射，保持现有交付及评测预算口径。

## Impact

- 主要涉及 `src/agent/` 的配置、工具协议、提示词和编排；提取 `run.ts` 内可复用的调用/记账逻辑，保留现有单智能体行为。
- 扩展 `src/records/` 的版本化记录与检查，更新 `src/evaluation/agents/statigent.ts`、`trajectory.ts` 及相关配置验证。
- 复用 `src/models/` 和 `src/execution/`；保持一个任务一个隔离会话，无需新增 Python 执行后端或编排框架。
- 更新任务/评测示例、使用文档、可控响应测试和 Docker 集成测试。真实模型仅通过显式入口运行，软件验收与正式研究结果分开记录。
