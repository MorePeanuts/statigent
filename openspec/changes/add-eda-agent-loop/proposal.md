# Proposal

## Why

Docker 持久内核、执行隔离和 Notebook 记录已完成，但当前示例仍执行固定代码，不能根据自然语言目标自主分析数据。下一步建立可配置模型驱动的单智能体 EDA 循环，作为第一章可独立使用的最小系统及后续规划—执行分离实验共用的基线。

## What Changes

- 新增模型配置与统一调用接口，首个真实提供商为 DeepSeek，调用名 `deepseek-flash`；供应商、协议、接口地址、密钥环境变量名、模型名和生成参数均可配置，兼容协议的模型可通过新增配置接入。
- 在宿主调用模型，复用已有 Docker 会话执行模型生成的 Python 单元；支持读取执行反馈、有限修复、连续探索和结构化完成，不向容器注入 API 密钥。
- 输入为分析目标、显式文件清单、必要约束和预算；输出为结论、统计口径、局限、可解析的证据引用及 Notebook。
- 加入模型调用、代码执行、修复次数、token 消耗和总耗时的预算管理，以及异常、取消、预算耗尽和记录失败的明确终态。
- 扩展运行清单与追加日志，关联模型请求、工具调用、Notebook 单元及最终结论；记录请求/返回模型标识、提示词版本、真实用量和未知成本，保持无模型运行及旧记录可读。
- 提供 CLI、合成数据测试与显式 DeepSeek 冒烟入口；默认检查和 Docker 集成不调用付费 API。

本次不实现规划者/执行者双角色、独立 Debugger、Benchmark 适配或评分、每轮新脚本消融、预测建模、网页界面、模型并行比较及服务器部署。支持自定义配置不等于已经验证所有供应商协议；代码重放不重新调用模型。

## Capabilities

### New Capabilities

- `model-access`: 可配置的模型连接、协议适配、响应与工具调用校验、有界请求、凭据隔离及调用身份和用量反馈。
- `eda-agent`: 基于持久会话的单智能体分析循环、执行反馈与有限修复、预算与停止语义、带证据的分析交付及独立测试入口。

### Modified Capabilities

- `execution-records`: 将清单、追加轨迹和成本统计扩展至真实模型调用，兼容既有无模型记录，区分代码重放和智能体重新运行。

## Impact

- 预计新增 `src/models/`、`src/agent/`、模型与任务配置示例、提示词和 CLI 入口；复用 `src/execution/`，扩展 `src/records/` 的清单版本、事件与读写校验。
- 保留现有 `runtime demo/inspect/export/replay/cleanup`，新增智能体运行与显式冒烟入口；不改变容器的断网和输入边界。
- Bun/TypeScript 负责模型和流程；优先使用内置 HTTP 能力及明确运行时校验，不预先引入多智能体框架。Python 与镜像依赖原则上沿用当前版本。
- 本地通过 `DEEPSEEK_API_KEY` 提供测试凭据；配置与日志仅保存非敏感配置。真实调用具有明确任务范围和预算，模型别名不被当成固定版本证明。
- 使用已有合成数据及新增小型夹具验收，不访问评分答案、不运行正式基准。研究定位依据 `docs/overview.md`，开发与正式评测区分遵循 `docs/benchmark.md`。
