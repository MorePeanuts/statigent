# Spec Delta

## Purpose

为探索性分析和预测建模提供身份明确、来源可追溯、可在统一任务协议下运行的研究对比方法，使方法机制、资源差异和实际验收状态可被核查，避免把工程夹具、改写方法或历史论文分数冒充同条件复现。

## ADDED Requirements

### Requirement: 两章的具名对比方法

系统 SHALL 提供 ReAct、AutoGen、DatawiseAgent 的文本、报告和预测任务配置，以及 AutoGluon 的预测任务配置。每种方法 SHALL 有独立身份、方法版本、公开输出能力和参数快照。纯 LLM 不属于本对比矩阵；确定性链路验收方法不得作为这些 baseline 的替代实现。

#### Scenario: 预览两章方法
- **WHEN** 用户预览分析与建模开发比较配置
- **THEN** 分别看到三种和四种外部 baseline，另列本方法及其消融；AutoGluon 不被派发分析报告任务

### Requirement: ReAct 方法边界

ReAct SHALL 使用单一模型角色交替决策、执行允许工具、读取实际反馈并完成任务，保留同任务历史。默认代码执行使用持久内核，明确记录文件复用与上下文规则；不得添加规划者委派、专门调试角色、协同笔记或本方法专属的证据完成门槛。报告/预测的公开交付约束仍须满足。

#### Scenario: 执行错误后继续
- **WHEN** ReAct 的一次代码执行产生普通错误且资源允许继续
- **THEN** 同一角色收到真实错误并自行决定修复或结束，不自动派发其他模型角色

#### Scenario: 与已有消融不等价
- **WHEN** 现有单角色 EDA 要求额外结构化 findings 和证据身份，而 ReAct 不要求
- **THEN** 二者使用不同方法身份及提示词配置，不因共享执行器而标为同一方法或复用其成绩

### Requirement: AutoGen 方法配置

AutoGen SHALL 使用固定官方版本的代码助手与执行代理交互配置，只有代码助手调用 LLM，执行代理不请求人工输入。方法清单 SHALL 明示角色、会话流程、代码执行状态、结束条件、循环上限与本地适配差异，不把执行代理描述为第二个 LLM 规划角色，不额外引入研究专用规划器或群聊选择器。

#### Scenario: 无人工的代码反馈循环
- **WHEN** 代码助手提交代码并收到执行结果
- **THEN** 执行代理将真实结果反馈给助手，任务无需人工输入；所有模型调用归入同一任务额度

#### Scenario: 依赖缺失
- **WHEN** 配置选择的官方版本或适配组件不可用
- **THEN** 预检明确失败，不回退成自写的 ReAct 循环并继续称为 AutoGen

### Requirement: DatawiseAgent 方法保真

DatawiseAgent SHALL 使用固定官方代码版本，保留其规划、增量执行、自调试、过滤与阶段转换逻辑；分析和建模配置分别记录来源。模型与执行边界的适配 SHALL 与上游源码分离并记录偏离，不将方法重写为本项目建模循环。依赖、必要输出或阶段隔离无法满足时 MUST 明确阻塞，不静默裁剪核心机制。

#### Scenario: 核心阶段仍实际运行
- **WHEN** 受控响应触发规划、执行错误、修复和过滤
- **THEN** 轨迹显示固定上游方法的实际阶段转换，并保留原提示词身份与执行反馈

#### Scenario: 上游配置要求联网安装
- **WHEN** 上游环境提示或生成代码要求临时联网安装依赖
- **THEN** 运行拒绝联网安装，依赖由事先构建的镜像提供，差异进入方法清单；不得为完成任务扩大网络权限

### Requirement: AutoGluon 的训练与预测边界

AutoGluon SHALL 使用固定官方表格训练版本、预设和模型集合，零 LLM 调用。预处理、验证、模型选择与集成仅使用允许训练数据；冻结模型后才读取测试特征并预测。运行记录 SHALL 保存实际参数、训练/推理时间、资源限制及模型身份，不将其伪装为执行过 EDA、LLM 搜索或 Statigent 确认流程。

#### Scenario: 与 Agent 混合运行
- **WHEN** 同一建模计划包含 AutoGluon 和 LLM Agent
- **THEN** AutoGluon 使用自己的训练流程和共同外层任务，模型调用用量为不适用，训练和总耗时实际计账

#### Scenario: 训练时限到达
- **WHEN** AutoGluon 到达配置的训练期限
- **THEN** 仅在已有有效模型且仍有预测额度时交付，并记录限时状态；无有效模型则失败，不自动提高预算

### Requirement: AutoGluon 的目标与指标适配

AutoGluon SHALL 支持当前协议的回归、二/多分类、等级标签、前三候选、多输出回归和多标签概率。类别顺序、正类、目标顺序和评分方向 SHALL 来自公开协议。特殊指标的内部选择映射与外层评分 SHALL 分开记录；允许使用预先固定的内部代理指标，但不得冒称与外层指标相同或依据测试结果更换映射。

#### Scenario: 前三候选与等级
- **WHEN** 任务要求前三候选或等级标签
- **THEN** 分别按固定类别概率排序生成互异前三项、按已声明等级集合生成合法标签；相同概率按冻结类别顺序打破并列，不使用测试标签确定类别

#### Scenario: 多目标共享预算
- **WHEN** 多输出回归或多标签任务对各目标分别训练
- **THEN** 每个目标的特征排除全部目标列及禁用标签字段，各目标共享任务总时限和资源，不能为每个目标复制完整额度；缺少任何必需目标时整份预测无效

#### Scenario: 无效指标值
- **WHEN** 内部验证出现协议未定义的指标值
- **THEN** 如实记录并按预定内部策略处理，不制造有效分数；外层评分始终使用基准冻结协议，不因代理指标改变

### Requirement: 方法来源与可复现环境

每种方法 SHALL 记录论文/代码来源、实现类别、上游 commit 或精确包版本、许可、提示词/适配版本、依赖锁和镜像身份，以及模型、执行后端、可用计算库和本地偏离。安装和镜像准备 SHALL 为显式操作；预检和任务运行不得自动下载、升级或安装。第三方源码 SHALL 保持原样，适配修改独立保存。

#### Scenario: 首次机器缺环境
- **WHEN** 用户在未安装 baseline 环境的机器预览配置
- **THEN** 返回具体缺失项和准备说明，不自动下载依赖，不把该方法标为已验收

#### Scenario: 修改方法配置
- **WHEN** 提示词、后端、上游版本或训练预设发生变化
- **THEN** 新运行具有不同配置身份和可核查差异，旧批次保持原值

### Requirement: 分层开发验收

系统 SHALL 为三套分析基准和两套建模基准提供固定开发范围，区分只读预检、受控响应、真实依赖/容器集成、真实模型冒烟和正式实验。默认检查不得调用付费 API或训练全量真实数据；真实冒烟 SHALL 显式指定方法、任务、模型、次数和总预算，保留首次失败，不自动换题或补跑。

#### Scenario: 无模型验收完整链路
- **WHEN** 合成任务使用受控模型响应和实际上游方法、实际执行容器
- **THEN** 验证方法路径、交付、隔离与成本协议，结果注明零付费验收，不据此宣称真实模型效果

#### Scenario: 真实方法失败
- **WHEN** 固定真实开发单元未能交付或独立预测复现失败
- **THEN** 保存原失败与成本，验收状态保持失败或不完整；修复后如有授权复测则创建新的运行身份
