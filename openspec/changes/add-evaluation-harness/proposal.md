# Proposal

## Why

当前 EDA 已具备真实模型执行、证据交付和成本记录，但尚无独立于智能体实现的真实任务评测流程。建立统一评测层，使新增基准与新增待测智能体分别通过适配器接入，为单智能体基线、角色分离消融和后续论文方法复现提供一致的实验入口。

## What Changes

- 新增版本化任务、智能体交付及评分契约，以及独立的基准和智能体注册入口；核心调度不包含某个基准的题号、答案或某个智能体的内部工具。
- 新增本地串行批次运行器：按显式任务集合、智能体配置和重复次数展开计划，预检能力与约束，管理逐任务和整批预算、取消、独立身份、记录及汇总。
- 首个基准接入已下载的 InfiAgent-DABench：仅发布题目和允许 CSV，私有答案仅用于运行结束后的确定性评分；保留上游比较口径，并明确修正缺失回答被忽略的汇总问题。
- 接入现有 Statigent EDA；提供隔离容器内的外部命令协议和无模型测试智能体，验证不依赖 TypeScript/Notebook 内部实现的替换能力。联网的第三方论文智能体需要以后增加经验证的接入配置，本次不宣称已经复现。
- 新增独立评测记录及 JSON/CSV 汇总，区分运行成功、答案正确、评分失败、预算合规和用量未知；保留原始智能体记录，不改变现有 schema_version=1/2 清单及代码重放语义。
- 提供无付费调用的快速/集成测试、固定小规模开发清单和显式 DeepSeek 真实验收入口。默认不运行全量基准，不自动重跑直到成功。

## Capabilities

### New Capabilities

- `evaluation-harness`: 配置驱动的评测计划、串行调度、预算与取消、批次记录、指标汇总和离线重新评分。
- `benchmark-adapters`: 基准任务发布与私有评分分离、数据版本与开发集合、InfiAgent-DABench 适配及原生评分口径。
- `agent-adapters`: 通用智能体调用与交付契约、能力协商、Statigent 接入、受控外部命令协议与成本来源标记。

### Modified Capabilities

无。评测层组合现有 `eda-agent`、`model-access` 和执行记录能力；各能力原有单次运行行为保持兼容，新增批次行为由上述规范承担。

## Impact

预计新增 `src/evaluation/`（契约、注册、运行器、记录、基准及智能体适配）、评测 CLI、`configs/evaluations/`、小型合成测试夹具和使用说明。复用 `src/agent/run.ts`、现有 Docker 隔离原则、文件校验和模型配置；Python 测试命令仍经 uv 执行。开发数据来自现有 `benchmarks/infiagent-dabench/`，上游文件保持原样，数据、答案、凭据与运行产物不提交 Git。

首版以 Bun/TypeScript、现有文件记录和本地 Docker 为主，不引入评测框架依赖、数据库、Web UI、分布式调度、并行执行、自动恢复、价格服务或插件下载市场。DAComp/DSBench、正式多模型实验及实际论文智能体复现为后续适配；本变更用注册扩展测试验证其接口边界。
