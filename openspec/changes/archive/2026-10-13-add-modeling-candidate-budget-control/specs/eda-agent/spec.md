# Spec Delta

## ADDED Requirements

### Requirement: 有界证据纠错与模型输出额度

系统 SHALL 明确区分执行单元身份与当前角色可引用的证据。失败单元的部分输出 MUST NOT 自动作为成功证据；引用校验失败时 SHALL 反馈失效引用、当前角色可用引用和剩余预算，引导模型重新验证或删除无证据结论，不自动替换引用或放宽角色隔离。纠正仍消耗既有动作纠正、模型和任务预算。

模型调用 SHALL 以请求 UTF-8 字节估计输入成本，实际输出上限取 profile 上限与“token 阈值减去已用量及输入估计”的较小值，并在请求和事件中保存。无法容纳输入估计与正输出额度时 SHALL 在派发前停止。输出上限裁剪 MUST NOT 增加任务额度、重置角色消费或伪造实际账单；已派发响应超阈值或用量未知继续沿用停止规则。旧请求及配置记录保持原样。

#### Scenario: 失败单元已有部分输出
- **WHEN** 执行者引用了已输出部分数值但最终失败的单元
- **THEN** 宿主拒绝引用，反馈合法列表；模型可在剩余预算内验证或只返回受已有证据支持的部分结果，规划者不收到未经接受的证据

#### Scenario: 剩余额度小于固定最大输出
- **WHEN** 剩余 token 能容纳输入估计与正输出量，但不足以容纳 profile 的最大输出
- **THEN** 请求向供应商传递裁剪后的输出上限，记录配置上限与实际上限，按真实响应消费结算

#### Scenario: 输入已无法容纳
- **WHEN** 剩余 token 不足以容纳保守输入估计与至少一个输出 token
- **THEN** 系统报告 token_preflight，未发送请求，不伪造模型消费
