# Spec Delta

## MODIFIED Requirements

### Requirement: 建模任务协议与指标事实

新建模记录 SHALL 保存目标结构、全部目标、特征白名单、主指标及实现版本、方向、预测契约、类别/等级映射、各目标正类、数值规则以及搜索/确认评价身份，关联实验、预测、EDA 和交付。可信分数 SHALL 带协议、分区、评价身份及必要的逐目标分项；训练指标仅用于诊断，失败和最终拟合不伪造分数。检查 MUST 核对搜索最佳、短名单、完整确认排名及最终选择，拒绝身份错位或无依据选择，不把诊断或确认分数回写搜索成绩。

#### Scenario: 最大化指标的最佳实验
- **WHEN** 检查 accuracy 从 0.7 提升到 0.8 的搜索
- **THEN** 搜索最佳为 0.8；最终选择 0.7 必须有合法终局确认依据，关闭确认时无此依据应报告不一致

#### Scenario: 平局与失败
- **WHEN** 后续搜索成绩与最佳相同或没有有效成绩
- **THEN** 搜索最佳保持先前实验，最终拟合不参与验证排名，确认失败不以部分成绩参与完整排名

#### Scenario: 分类证据协议错位
- **WHEN** EDA 来源实验相同但类别映射、正类或预测哈希与冻结来源不一致
- **THEN** 检查拒绝有效证据声明，不因文本写了正确实验 ID 就接受

#### Scenario: 逐目标指标伪装为整体成绩
- **WHEN** 记录把某目标 AUC 写成全部目标平均 AUC
- **THEN** 审计按目标集合和冻结权重核验并拒绝错误聚合，不接受同名数值替换

### Requirement: 表格建模记录的版本兼容

新父运行、目标协议、阶段、动作、笔记、分配与交付格式 SHALL 显式版本化；系统 MUST 继续读取、检查、复现和评分既有合法 schema 1/2/3/4 建模记录，遵循原镜像、输入、划分、指标及容差，不原地迁移。新运行可显式引用旧数据及任务配置并保存版本映射，不改历史协议身份。新格式缺字段或版本未知 MUST 拒绝，不按旧格式猜测目标、方法或笔记。独立操作不得改写原运行文件。

#### Scenario: 历史回归交付
- **WHEN** 用户对旧回归运行执行 inspect、reproduce 或 score
- **THEN** 按原协议工作，兼容视图中的通用指标明确来自原 RMSE，原运行和交付哈希不变

#### Scenario: 旧数据用于新运行
- **WHEN** 新程序以显式新版任务加载合法旧数据清单
- **THEN** 保留原输入及精确搜索划分，记录新运行、兼容解释与可选确认计划，不覆盖旧数据

#### Scenario: 新记录缺失字段
- **WHEN** 新版父记录缺失必需方法、评价身份、类别或选择依据，或声明未知版本
- **THEN** 检查与复现拒绝并报告协议错误，不假设 RMSE、默认正类或静默关闭确认

#### Scenario: 历史分类交付
- **WHEN** 对 schema 2 分类运行执行检查、预测复现或离线评分
- **THEN** 保留原类别映射、概率顺序和原选择规则，不要求新增认识及确认字段

#### Scenario: 历史完整协同记录
- **WHEN** 检查或复现 schema 3 的完整协同运行
- **THEN** 按原候选、认识、确认及失败语义检查，保留原产物，不把其改写为新笔记或保护交付

#### Scenario: 简化流程的既有记录
- **WHEN** 检查 schema 4 的可选笔记与保护交付记录
- **THEN** 保持原动作、笔记、搜索结束与交付语义，不因新增多目标协议或分阶段预测补造事件

## ADDED Requirements

### Requirement: 基准来源与准备事实关联

建模评测 SHALL 关联目录版本、准备记录、原始数据及外层成员、内部划分、预测导出、评分协议/参考来源和原生运行身份。私有材料只在评分侧保留内容及路径，模型可见协议不含私有成绩或答案。准备复用、父任务消费、独立评分及复现耗时 SHALL 分列且不重复，原始数据和历史清单保持只读。

#### Scenario: 从 RPG 追溯原生分数
- **WHEN** 用户检查 DSBench 的某项 RPG
- **THEN** 可追溯固定参考来源、原生测试指标、冻结预测和原生建模运行，不把参考成绩写入智能体上下文

### Requirement: 冻结模型与分阶段预测事实

记录 SHALL 区分搜索结束、确认、最终拟合形成冻结模型、预测请求和完整预测交付，保存每次预测输入、模型及产物哈希。拟合已完成但尚无预测时不得记完整预测交付；失败预测不改写先前模型或重开搜索。预测请求 MUST 关联自己的实际耗时和复现状态，不复制原 LLM 用量。

#### Scenario: 同一模型预测两份输入
- **WHEN** system 适配器合法请求两次预测
- **THEN** 保存两份独立预测事实，共享同一冻结模型身份，模型搜索成本只记录一次

#### Scenario: 预测失败后检查模型
- **WHEN** 已冻结模型的后续预测超时
- **THEN** 检查显示模型已冻结、该预测失败和交付未完成，不覆盖为搜索失败或成功空交付
