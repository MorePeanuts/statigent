# Design

## Context

动机和范围见 [proposal.md](proposal.md)。探索已核对本地实现、规格、候选元数据及 52 项 DSBench 评分脚本，不需要在实施时重新开展泛化架构调研。

- `src/evaluation/registry.ts` 仅注册三套分析基准和合成基准；`contracts.ts` 为 v2，只接受 text/report，指标要求有限上下界。批量计划、串行派发、取消、冻结交付、重评和覆盖率已有实现。
- `src/modeling/protocol.ts` 为单目标协议 v1，仅有 RMSE/accuracy/ROC AUC/log-loss；`data.ts` 全量读取 CSV，固定 32 MiB；`profile.ts` 和 Python 概览限制 128 列。Python 评分器还有独立 32 MiB 常量。已下载任务存在更大文件和更宽表。
- `run.ts`、`finalize.ts`、`experiments.ts` 和 `delivery.ts` 已支持四种方法、确认与交付，但最终拟合与测试预测绑定。Python runner 调用 `build_pipeline(seed)`，接收单列目标，保存模型；模型仅在 Docker 内反序列化。
- 52 项 DSBench 是下载候选而非研究资格审计结果：包含 s4e3 七目标、s3e18 双目标、s3e13 前三候选、有序评分及时间语义任务。s3e18 的 EC3–EC6 是训练独有标签，不能进入测试时不可用的特征。
- TabArena 本地 v0.1 元数据为 13 项 regression/RMSE、30 项 binary/AUC、8 项 multiclass/log-loss。数据 revision 固定在 `benchmarks/metadata/revisions.json`；它不等于官方 Python 接口的 Git commit。
- 现有研究文档要求 system 接入；[官方 system 示例](https://github.com/autogluon/tabarena/blob/main/examples/benchmarking/run_quickstart_tabarena_system.py)使用独立训练入口及 predict/predict_proba，由系统自行管理训练内验证和搜索。该链接用于接口调查，实施验证前必须另行固定代码 commit 和依赖，不跟随 main 漂移。

## Goals / Non-Goals

**Goals:**

- 以公共任务契约隔离基准准备/评分与智能体，内部验证和外层测试共享明确的指标定义。
- 实现支持所有候选所需指标/预测形式的能力；每个候选都有可解释的审计和资源状态，避免通过静默删题隐藏缺口。
- 使常规 CLI、本地批量评测、官方 system 桥接共用建模核心和隔离执行，分别保留阶段与成本事实。
- 将全候选静态验证、确定性真实数据验证、小型真实智能体验收和正式实验区分为独立证据层。

**Non-Goals:**

- 不在本变更承诺 103 项候选都符合研究范围、都能在当前机器训练或都必须纳入正式实验。
- 不改变协同方法、上下文策略、两份内部确认的选模规则；不增加通用多输出回归、时序专用搜索或其他无候选需求的任务类型。
- 不实现官方排行榜/Elo、跨硬件成本优势、全部 AutoML/研究基线或基于成绩的自动任务筛选。
- 不在普通检查自动下载数据、初始化官方全量运行或请求付费模型。

## Decisions

### 1. 扩展统一评测，基准准备与评分独立

沿用 `src/evaluation` 的 Registry 和主循环，新增 `dsbench-modeling`、`tabarena-lite` benchmark adapter，以及 `statigent-modeling` agent adapter。准备和审计置于基准侧模块，计算用 Python，经 uv 和已有结构化进程协议调用。不得在 `src/modeling/run.ts` 按题号分支。

```text
Raw data + pinned sources --> Audit/catalog --> Prepared task
                                                 |
                                      Evaluation plan (v3)
                                                 |
                                    Statigent modeling adapter
                                                 |
                              Search --> Confirm --> Frozen model
                                                        |
                  Deferred test features --------------> Predict
                                                        |
                                               Frozen predictions
                                                        |
                  Private labels + references --------> Score --> Report
```

备选是独立建模 batch CLI；它会重复预算、取消、未运行与重评语义，因而不采用。现有 `modeling prepare/run/inspect/reproduce/score` 入口保留；新增基准准备/审计作为 `evaluate` 子命令，`evaluate plan/run/inspect/score` 继续统一操作。

### 2. 全量目录与实际运行资格分开

新增可提交的 `benchmarks/metadata/modeling-task-catalog.json`，记录 52+51 个候选的公开适配事实和来源哈希。大的精确成员、标签和本机验证输出留在运行目录；私有参考数值不放入智能体公开目录。

每项至少包含：benchmark/source revision/task ID；公开题面与数据文件身份；目标列表与排除字段；原始行身份及特征类型；指标参数；预测导出列；外层划分身份；已知冲突；研究资格 `eligible/review_required/excluded`；适配状态 `ready/blocked` 及原因；独立的 `preflight/deterministic/live` 验收结果。未运行不能标为 passed。

`evaluate audit` 扫描全部候选，不训练。它核对训练和测试特征结构，受信准备端检查标签结构/对齐但不按标签成绩选题；扫描中的测试标签不进入公开输出、类别推断或模型配置。协议缺失、未知目标、坏文件必须定位到任务。

资源不兼容与指标实现缺失不同：全指标任务不得以 `unsupported_metric` 作为交付完成的常态；尚未解决的协议冲突和资源限制可明确阻塞。对时间/组语义疑问保留原 DSBench 发布划分、禁止自动改成未来预测实验；正式清单必须先解决研究资格。实现不改写原下载选择文件来抹除历史。

### 3. 准备数据时保存特征语义与阶段权限

准备输出分为公开任务描述、search/training 数据、final-prediction 特征和私有 evaluator 数据。宿主路径只由受信调度使用，模型消息没有私有路径；挂载按执行阶段建立。即使公开原始 test.csv 可在磁盘找到，也不能自动加入搜索挂载。

- DSBench 保留发布 train/test 成员。优先保留有效唯一 ID，否则以固定源行号生成碰撞安全 ID，保存原始导出映射。模型特征为任务明确白名单，不能简单把“不是主目标”的所有列都作为特征。
- TabArena 从原始 ARFF/Parquet 保留物理行号，与官方 r0f0 索引精确映射；验证重复/越界/交集/覆盖。记录原始文件和分片哈希，不依赖元数据的平均行数。
- 保留字段类型、名义类别、缺失标识以及实际字符串；防止 pandas 把类别 `NA`、`01` 当缺失或数值。ARFF 缺失 `?` 与真实字符区分，导出 CSV 附带明确类型/缺失策略。类别顺序和正类从允许训练数据与固定接口语义确定，不能读取测试标签修补。
- 新的数据/记录版本保存完整特征描述；模型提示只展示有界摘要，并提供受控可读的完整描述文件。不得为了 128 列摘要上限删除数据列或拒绝本已可处理的宽表。

文件、行列、字段长度、内存和时间配置集中传递到 TypeScript 与 Python 入口，替代散落的固定 32 MiB 拒绝。新基准配置显式声明准备限额，旧配置保持原值。准备、哈希与评分采用分块读取；需要全量向量的排名指标保留有界内存预算并提前估计。TS 控制层以文件描述/精确成员引用为主，避免在消息中重复复制整表；Python 模型仍须在声明内存内拟合。

依赖优先复用 scipy/pandas；完整 ARFF 解码若现有能力不能覆盖名义/字符串/稀疏编码，则在数据准备依赖组锁定专用解析器；Parquet 使用锁定的 pyarrow。只处理可信声明的数据格式，不执行嵌入内容。新增依赖及锁文件在实施阶段提交，原第三方文件不修改。

### 4. 通用目标/预测协议 v2，旧协议身份不变

新协议采用 `targets[]`、任务 kind、特征语义、指标描述及预测描述。kind 为 regression/binary/multiclass/ordinal/multilabel；本次 multilabel 仅包含多个二元目标。有序类别同时保留字符串身份、连续训练编码和评分用等级坐标。

| 输出类型 | 规范产物 | Statigent 生成方式 |
| --- | --- | --- |
| numeric | ID + 单目标有限数值 | predict 后还原原始尺度 |
| label | ID + 原始标签 | predict 的训练编码映射回原标签 |
| probabilities | ID + 派生标签 + 完整类别概率 | 按 classes_ 映射对齐，平局取冻结顺序 |
| multilabel-probabilities | ID + 每目标标签/两类概率 | 按 targets[] 分别映射，导出所需正类列 |
| ranked-labels | ID + 有序候选列表及可用概率 | 完整多分类概率稳定排序取最多三项 |

外部预测适配可直接提交合法候选列表；不能因此要求所有外部方法返回模型或全部概率。基准导出格式另有映射，例如 s3e13 用空格连接候选名；若类别身份不能无歧义序列化则预检阻塞，不擅自改类别字符串。

`build_pipeline(seed)` 工厂保持不变：普通任务 `y` 为一维编码，multilabel 为按目标排列的二维编码，模型须返回可按每目标 classes_ 对齐的概率。同一 saved estimator 保存协议和目标映射，支持能处理多目标的流水线或标准多输出包装；不隐式为模型新增训练搜索。

单目标分层算法与旧协议保留。新 multilabel 默认按稳定样本 ID 和种子排序取 80/20，全目标逐一检查两类覆盖；显式成员可覆盖默认。确认沿用两份预先派生种子，验证彼此不同及全目标覆盖；失败明确拒绝，不能循环试种子。需要未来改用迭代分层时引入新算法版本，不改变已冻结成员。

旧 v1 使用原 epsilon、类别及容差；新版 v2 引用具体 metric definition，不把旧哈希重新序列化成新格式后冒充同协议。

### 5. 指标实现集中，按实际上游算法建立变体

建立共享指标注册表：TS 校验 ID、方向、输出要求与参数，Python 执行实际评分。评分桥接只传校验后的文件引用和协议，不加载 candidate/model。搜索、确认、诊断和外层调用相同定义，区别仅在数据成员与阶段身份。

| 指标族 | 关键参数/边界 |
| --- | --- |
| RMSE / MAE / MedAE | 原始目标尺度，有限预测，无上界 |
| RMSLE | np.log1p 型和 sklearn 型的有效域分别登记；禁止评分器静默裁剪 |
| R² | 固定常量标签和 force_finite 行为，无有限下界 |
| SMAPE | DSBench 为 2×绝对误差/绝对值和的均值、范围通常为 0–2；双零行为绑定实现版本 |
| accuracy / micro-F1 | 原始类别语义，不因数学上有时相等而丢失原指标身份 |
| ROC AUC / log-loss | 正类/类别顺序、并列、epsilon、归一化与单类失败规则 |
| normalized Gini | 原实现按预测降序、原行序解平局，不能直接替换为 2×AUC−1 |
| quadratic weighted kappa | 等级坐标和固定 N；s3e5 使用原整数等级与 N=10 |
| top-k hit | s3e13 固定 k=3、无位置权重，不能写成 MAP@3 |
| mean target AUC | 各二元目标独立概率、固定全目标等权，无部分成功平均 |

DSBench 主协议使用固定发布实现的实际行为：s3e23 的 `rmse` 变量实际是 AUC，s3e20 的 `smape` 变量实际是 RMSE；s3e13 的文字与命中实现不同；s3e19 双零会产生非有限值。任务目录必须显式登记这些差异。评分器对未定义输出给出错误，不在本变更新增“修正分数”与兼容分数混用。若未来需要修正协议，独立版本、结果和参考分数再评估。

评分对齐是本地明确改进：先按固定基准评价成员顺序对齐合法 ID，再传数值给指标函数。原脚本多处 `sort_values` 未赋回，不能复制其按错行计算的危险行为；差分测试向上游提供已经对齐的输入，另测本地乱序输入等价和重复/缺失拒绝。Gini 平局顺序保存为评价身份的一部分。

各逐题脚本用固定合成输入与原源码运行做差分，记录异常、非有限及容差；不使用 `eval` 解析上游索引或结果。RPG 参考压缩包只按允许的 baseline/GT 路径安全提取/读取，拒绝越界成员，保存 zip/成员哈希；参考缺失、分母零或方向不符使任务评分协议阻塞。

### 6. 拟合与预测解耦，保留普通完整运行

从 `finalize.ts` / `experiments.ts` / `delivery.ts` 抽取两个阶段：

- `fit`：使用允许训练数据完成搜索、确认、最终拟合，产生冻结模型清单，状态为 `model_frozen`，没有完整预测交付。
- `predict`：对受信调用声明的特征执行隔离预测，校验输出，形成独立预测记录与完整交付。不得调用 LLM、修改模型或重新确认。

普通 `modeling run` 和本地 evaluate 将两步顺序组合，原整体超时/取消和收尾预留仍覆盖最终预测。fit-only 的预留覆盖确认/最终拟合，后续预测有独立有限预算；记录模式差异，不能在同预算研究比较中不披露。已冻结模型与每次预测各自不可变，失败预测不重开搜索。

TabArena 薄 Python wrapper 调用受信 Bun 桥接，适配官方 `_fit_system`、`_predict`、`_predict_proba` 和 cleanup。训练输入只有 X/y；持有原生冻结模型引用，预测在 Docker 中完成，宿主不 joblib.load。Python wrapper 不是另一个智能体，模型请求仍由 TS 负责；环境白名单和取消信号沿桥接传递。CPU/内存/时间低于必需条件或要求当前不支持 GPU 配置时预检拒绝，不忽略官方约束。

官方接口和指标实现需单独固定代码 commit、依赖锁及来源记录；通过可选 uv 验证环境安装，默认镜像和快速测试不依赖官方大环境。用可控模型及小型合成任务跑一次真实官方 system 调用链，核对类编码、返回形状、原指标/官方误差方向映射、资源/种子以及无外部 HPO；再对本地选定 r0f0 开发任务比较原生评分。不得使用官方缓存预测替代本次结果。正式发布排行榜和官方全量调度不在此范围。

### 7. 评测 v3 的交付、汇总和失败语义

`PublicTask` 新增 predictions 输出及阶段化输入描述；`Capabilities` 声明 predictions 与阶段隔离支持。`Metric.minimum/maximum` 可为 null，value 仍必须有限。新批次统一 v3，v1/v2 分支保留数值与冻结语义；旧 container-command 的流式协议不顺带升级或获取新权限。

模型留在原生目录，评测只冻结规范预测、官方导出预测和足以离线解释它们的公开协议清单，记录原生模型/交付哈希。评分仅依赖冻结预测、私有标签及可信评分代码；predict/refit 复现才需要原生模型/代码。预测限额独立配置、全链路一致，不能盲目扩大普通报告限额。

| 情况 | 原生预测指标 | 完成率/归一化结果 |
| --- | --- | --- |
| 有合法预测 | 按协议真实计算 | 预测有效性成功；模型交付/复现另列 |
| 已执行失败或非法预测 | null，保留原因 | 完成率计失败；DSBench RPG=0 |
| 未运行 | null | 固定计划保留，完整汇总为空 |
| 标签/参考损坏、指标未定义、评分故障 | null，scoring failed | 覆盖不完整，不能当普通答错计零 |
| 保护交付成功但模型用量未知 | 可独立评分 | 记账不完整、非自主完成、停止后续受预算约束派发 |

TabArena 首版输出逐任务各方法/种子配对表、完成率和成本，跨任务不直接平均 RMSE/AUC/log-loss。DSBench RPG 不截断大于一的值，并明确其 GT 不是同硬件重新训练基线。原 `cross_agent_summary` 排行榜选项保持不支持，新的配对导出使用独立明确入口，不伪造 Elo。

准备数据复用是显式只读复用：记录一次准备事实和每个批次的复用引用、校验开销，单元各自生成实际基础概览及内部执行状态。父账已含子 EDA，评测不能重复加总；重评和复现另计。

### 8. 按风险分层验收，不按任务成绩挑选

| 层次 | 范围与验收证据 |
| --- | --- |
| 快速 | 全指标合成边界/差分夹具、TS/Python 协议一致、目标/概率/ID 校验、批次聚合及旧记录兼容 |
| 上游 | 对固定 52 项脚本的所需调用口径逐项差分；TabArena 固定版本指标与 system API 兼容，独立显式入口 |
| 全候选 | 52+51 元数据/来源/结构/划分/资源审计；准备验证按显式资源执行，任何阻塞与未检查项进入报告 |
| Docker | 合成回归、普通分类、有序类别、多目标及前三候选的搜索—诊断—确认—拟合—预测—复现；隔离和错误/取消/限额 |
| 确定性真实任务 | 小型真实清单及各特殊协议代表，实际拟合/预测/评分、独立预测复现，无 LLM；全量候选训练另选任务与总预算 |
| 真实智能体 | 固定清单上明确授权的方法/种子/模型/资源范围，保留失败，不自动补跑；四组配置先无模型预览 |
| 正式实验 | 后续冻结研究资格、数据重叠处理、任务、模型/基线、预算、重复和失败规则，非本变更验收 |

初始开发候选依据公开规模与覆盖：DSBench s3e9（回归，已开发暴露）、titanic（二分类）、s4e2（多分类）；TabArena airfoil_self_noise 363612、blood-transfusion-service-center 363621、maternal_health_risk 363685。特殊形式补充 s3e5（等级）、s3e13（前三候选）、s3e18/s4e3（双/七目标）。这是待预检的候选列表，不代表已冻结或已验收；按预检结构/资源问题调整必须记录理由且发生在真实调用前，绝不按模型分数选题。

每种指标至少有独立合成差分，每种任务/输出结构至少有 Docker 和确定性真实数据代表；真实 LLM 验收不必把所有指标乘四组全跑一遍。实际执行范围、资源和候选变更在调用前提交。无授权付费范围时仅交付入口与未执行状态，不把该任务勾成真实验收通过。

## Risks / Trade-offs

- [上游口径不一致或有未定义边界] → 保存实际实现及差分证据，明确阻塞/评分错误；修订口径使用独立版本，不静默纠正。
- [覆盖指标扩大到新的目标结构] → 按协议、执行、适配、验收分阶段提交，先证明多目标和前三候选的完整链路，再扩批量运行。
- [全量数据与宽表超过当前内存/产物额度] → 有界分块准备、文件引用与统一限额；配置预检和明确资源阻塞，不默认无限提升额度。
- [多目标稀有类别导致确认无效] → 冻结前检查每份划分类别覆盖；本次不新增反复试划分机制。
- [官方 system 版本与数据版本混淆] → 独立固定两个身份，官方调用兼容验证失败不得写成已接入；默认运行避免拉取 latest。
- [解耦拟合/预测影响现有收尾和成本] → 普通模式保留全流程父预算；fit-only 单独声明，取消/未知执行仍禁止新拟合，保护交付不冒充自主完成。
- [研究候选混有时间语义或同源数据] → 审计输出研究待决项，不把发布随机划分解释成未来预测能力，正式集合在后续单独冻结。
- [两个基准全部任务训练成本过高] → 全候选审计与完整训练分开，实际未训练项如实记录，不能把全指标测试通过当作全量实验完成。

## Migration Plan

1. 在独立任务分支按阶段交付：来源目录和冻结协议 → 指标/目标核心 → 隔离执行与复现 → 评测适配 → 官方兼容及分层验收。
2. 新数据清单 v3、目标协议 v2、执行 stage v4、建模任务 v4/父记录 v5/交付 v5，以及评测 v3 分别按自身版本解析；已有数据 v1/v2、stage v1/v2/v3、父记录 v1–v4 和评测 v1/v2 保留只读解释与原镜像语义。版本号对应各自 schema，不混用。
3. 旧分析配置保持可启动；现有合法建模任务配置可通过显式内存适配运行，记录源版本，不能重写原文件或改变旧记录。新特殊任务只能使用新协议，未知版本一律拒绝。
4. 更新镜像能力检查和新协议兼容检查，新任务遇旧镜像在首个 LLM 前拒绝。默认冒烟预算不隐式扩大，新增资源文件与开发清单另行提交。
5. 验证旧真实记录读取/重评/预测复现，源目录哈希不变；回退到旧代码时仅运行旧配置和旧记录，保留所有新产物。代码回退不删除数据、不篡改新结果为旧格式。

## Open Questions

- 全候选审计后哪些任务因数据/题面冲突或研究时间语义需要保留为 review_required：输出问题清单即可，不阻止通用指标和适配能力实现；不得未经研究决策将这些任务放入正式清单。
- 真实付费验收使用的模型、精确任务/方法组合及总预算：在软件与确定性验证后冻结，现阶段不发起调用。
- 官方 system 兼容环境的具体可安装 commit 与依赖锁：实施第一阶段记录并验证；所需调用边界已经明确，不以改变接口语义绕过安装或兼容失败。
