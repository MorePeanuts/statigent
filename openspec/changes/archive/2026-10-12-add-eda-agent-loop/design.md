# Design

## Context

动机与范围见 [proposal.md](proposal.md)。已检查 `src/cli.ts`、`src/execution/{protocol,session}.ts`、`src/records/{store,notebook,replay}.ts`、现有测试和三份主规范：

- CLI 的 `DEMO_CELLS` 是固定代码；已有 `DockerSession.execute/cancel/close` 可直接复用，执行和关闭均有明确状态。
- 执行反馈已有预览、单元身份、产物引用及完整度；Python 错误不回滚，丢失内核后不能假定状态仍存在。
- `Manifest` 只支持版本 1，模型、提示词、token 固定为 `not_applicable`；`readManifest`、Notebook 导出和重放均需兼容扩展后的记录。
- 当前 `manifest.config` 供重放提取执行配置，不能直接换成不兼容的智能体配置结构。现有记录器的最终执行失败保护也不能被智能体的完成声明绕过。
- `bun run check` 为快速检查，`test:integration` 包含真实 Docker 和内核，均应继续不调用模型。所有新增控制逻辑使用 Bun/TypeScript。

用户已确定首个提供商为 DeepSeek、请求模型名为 `deepseek-flash`，并授权本地测试读取已有 `DEEPSEEK_API_KEY`；这里只确认了环境变量存在，规划阶段没有发送付费请求。后续需要多模型比较，因此模型名称与供应商特有字段不得进入智能体决策逻辑。

2026-10-12 核对的官方依据：[调用地址与模型别名](https://api-docs.deepseek.com/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[推理模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[用量口径](https://api-docs.deepseek.com/quick_start/token_usage/)。当前别名对应 DeepSeek-V4.1-Flash；这不是固定权重或不可变快照的保证。

## Goals / Non-Goals

**Goals:** 在现有隔离运行时之上建立可测试的单智能体服务边界；模型接入、动作循环、预算、记录分别实现；为后续角色分离复用接口，而不提前构建角色调度平台。

**Non-Goals:** 本次不引入多智能体框架、供应商自动降级、跨任务记忆、后台代码任务、自动续跑、通用宿主 shell/文件工具或自主联网。支持生成并交付 PNG，但模型首版仅消费文本反馈和图表引用，不增加视觉输入链路。其他业务边界以 proposal 为准。

## Decisions

### 1. 具名配置与模型适配边界

模型配置分成可序列化的 `ModelProfile` 和仅在调用时解析的凭据。建议 `configs/models.json` 保存具名配置，任务文件通过 `model_profile` 选择；CLI 可覆盖配置文件路径及配置项名称，不通过自由拼接参数覆盖内部工具或请求历史。

DeepSeek 默认配置的设计形态：

```json
{
  "id": "deepseek-flash",
  "provider": "deepseek",
  "protocol": "chat-completions",
  "base_url": "https://api.deepseek.com",
  "model": "deepseek-flash",
  "display_name": "DeepSeek-V4.1-Flash",
  "api_key_env": "DEEPSEEK_API_KEY",
  "capabilities": { "tool_calls": true, "thinking": true },
  "generation": {
    "thinking": "enabled",
    "reasoning_effort": "high",
    "max_output_tokens": 4096
  }
}
```

推理开启及 high 是本次开发预设，并非用户要求或实验最优结论；允许配置关闭，所有有效参数必须入档。DeepSeek 适配器将通用字段映射为实际 API 参数；不发送在所选模式下无效的 temperature 等字段。用户显式设置不受支持的参数组合时提前失败，避免看似不同的实验实际使用相同参数。

首版提供 DeepSeek 适配器和通用 Chat Completions 工具协议适配器，两者共享 HTTP 与归一化逻辑。配置中 provider 与 protocol 分开：前者决定能力和参数映射，后者决定传输格式；未知 provider 只能显式选择通用已支持适配器，不能猜测兼容性。模型名不枚举，提供两个不同配置的假服务测试切换；其他协议以后增加适配器，不用修改 EDA 循环。

采用 Bun `fetch` 非流式请求，读取响应体时分块限额后再解析 JSON；设置 AbortSignal、超时和 `redirect: error`。地址由可信配置指定，默认 HTTPS，仅为显式本地服务/测试配置允许 loopback HTTP，不允许 URL 内嵌凭据。不接受任意未经校验的 headers 或 request-body 扩展。

理由：第一版集中验证工具循环，不需要流式 UI 或通用 Agent SDK。运行时结构校验覆盖配置、HTTP 返回、工具参数和清单，类型断言不能替代校验；优先沿用已有显式校验方式及共享工具定义，新增库需说明必要性并锁定版本。

### 2. 单智能体服务和严格动作协议

建议边界为 `src/models/` 管理调用，`src/agent/` 管理任务、动作和预算，现有 `src/execution/` 只负责 Python，`src/records/` 统一持久化。公开运行入口接收目标、约束、显式输入、模型配置、执行限制、智能体预算和取消信号；返回 `run_id`、终态、诊断、结果引用和 Notebook 状态。

首版向模型提供两个函数工具：

- `execute_python({code})`：在当前会话执行一个单元，返回已校验的 `ExecutionResult` 摘要和本次证据引用。
- `finish_analysis({summary, findings, methods, limitations})`：提交最终分析。每条 finding 包含 `statement`、可选结构化 `value` 及 `evidence_refs`；引用为当前运行成功单元的 `cell_id` 或已保存 `artifact_id`，不接受宿主路径。

每次响应只允许一个工具调用。若包含多个调用，先检查整个响应并全部拒绝，分别为可辨认调用 ID 返回对应拒绝结果以保持协议历史一致，不执行其中任何一个；缺失/重复 ID 等无法构成合法历史的响应直接失败。普通 assistant 文本可入轨迹，但不能完成任务，也不能从 Markdown 中提取代码执行。无合法动作的可纠正响应计入动作纠正额度。

循环为：校验任务及输入/凭据 → 创建记录与容器 → 检查预算并记录请求意图 → 调用模型并持久化响应/用量 → 校验一个动作 → 执行或验证完成 → 保存反馈 → 继续或收尾。多步复用同一内核，不自动重启。预算检查、取消信号和持久化失败均可阻止下一次派发。

工具名称、调用目标和资源配置由宿主决定，模型不能修改。模型仅获得挂载路径 `/input/...`、目标、约束和有界执行反馈，不获得真实宿主路径、环境变量或整个仓库。任务文本和数据只能影响分析内容，不能改变控制权限。

### 3. 反馈、错误修复和上下文

保留模型消息与工具响应的完整有界历史，不在首版自动摘要或静默丢弃旧单元。DeepSeek 推理模式下，工具请求所需的 `reasoning_content` 等历史字段由适配层保留并回传；它们不进入最终分析报告，也不作为结论证据。此行为需要含工具调用和无工具调用历史的假服务回归。

工具反馈包含状态、预览、预览截断、保存完整度、单元身份、内核可用性、部分修改说明和产物索引。对过长预览，模型可重新计算较小摘要；本次不添加通用宿主产物读取工具。图表引用注明未送入视觉模型，模型应以实际统计值支持结论。

普通 Python `error` 在内核可用且内容保存完整时允许修复，每次提交新单元；连续错误后最多再尝试 2 次，成功执行重置连续代码错误计数。非法动作最多允许全任务 2 次纠正请求，模型调用次数独立累加。工具结果未知、内核丢失、协议失效、输出保存超限以及代码单元超时/取消均停止本次智能体任务；执行底座允许恢复的能力仍保留给其他调用方。

不暴露 Notebook 重启工具，避免模型通过重启掩盖状态丢失。HTTP/协议错误、代码错误、分析无法完成分别记录；未确认的代码不重发。默认不增加独立 Debugger。

### 4. 预算与请求终止

预算由宿主统一检查，所有数值可配置并运行时校验。以下是小型合成任务的初始开发值，需在实施时用真实结果核对并记录最终值：

| 限制 | 初始值 | 计数/停止口径 |
| --- | --- | --- |
| 模型 HTTP 尝试 | 12 | 首次及重试均计数；未发送不算调用 |
| 实际代码单元 | 8 | started=true 才计数，拒绝工具不算执行 |
| 单请求输出 | 4,096 tokens | 映射为服务支持的上限，包含推理时遵循其口径 |
| 累计 token 停止阈值 | 100,000 | 每次真实响应结算输入+输出，缓存/推理明细不重复累加 |
| 请求时限 / 全任务时限 | 90 秒 / 300 秒 | 每次请求使用剩余任务时间与请求上限的较小值 |
| 限流重试 | 最多 2 次 | 同时占用 12 次总尝试和总时限 |
| 单次请求体 / 响应体 | 256 KiB / 2 MiB | 编码后字节数；到限停止，响应不无限读入内存 |
| 模型轨迹累计内容 | 16 MiB | 与执行输出配额分开，超限停止并注明未保存范围 |

请求前以有效历史和输出额度作保守估算，并检查已知消耗；首版将实际请求体 UTF-8 字节数作为输入 token 的保守估计，方法标为 `utf8_bytes_estimate`，这不是服务 tokenizer 的精确值或数学上界。当已知消耗加估计输入和单请求输出额度超过阈值时，不发送新请求。估算方法及数值单独入档，不冒充服务 token 统计。累计 token 是停止阈值，实际值可能由最后一个请求跨过，跨过后不执行其工具或发新请求。严格的费用上限不能由估算保证；当前硬约束为次数、时间、请求/响应大小和单请求输出限制。不引入价格硬编码或将估计 token 换算成精确账单。

请求成功但缺失用量时保留响应、将消费标未知并停止任务，终态 failed/accounting_incomplete；已经发送但超时、断流或不明确的 5xx 同样不自动重试。仅明确拒绝生成的可重试限流使用有界退避，不把不明失败归为免费重试。401/403、请求参数和协议错误不自动重试。返回用量的失败尝试仍按实统计。

全任务时钟从开始运行而非容器 ready 起计，包含预检、启动、模型等待和代码执行。复用执行层时按剩余任务时间配置会话；宿主总计时负责模型等待阶段，清理使用独立有界宽限并计入总墙钟。预算耗尽、取消或超时后不再花一次模型调用生成总结，返回已记录观察和确定性状态说明。次数预算按动作检查：代码次数已满但模型预算仍充足时，可请求最终完成；新的执行动作才被拒绝，不能在最后一个允许单元成功后立即阻断合法完成。

### 5. 清单演进与统一轨迹

引入清单 schema_version=2，新写入清单使用版本 2；读取器同时验证 1/2，版本 1 不原地迁移。`model/prompt/tokens` 使用“not_applicable 或经校验结构”的联合表示，新增 `run_kind` 区分 runtime、agent、code_replay；新增 agent 字段记录任务目标、预算、剩余量、最终结果引用及终止原因。扩展模型信息不能破坏现有图表、Notebook 和文件校验功能。

保留 `manifest.config` 的原执行配置形态，智能体配置单独记录在 agent 字段，模型配置单独记录在 model 字段；重放从执行配置提取所需字段，不将模型调用信息带入新代码重放成本。种子仅描述实际设置的位置，不声称 Docker 随机种子固定远端模型采样。

追加事件新增 `model_request`、`model_response`、`model_failure`、`tool_validation`、`agent_budget`、`agent_finish` 等命名，与已有 `dispatch/finish` 区分，防止 Notebook 构造器将模型终态当成单元终态。每次尝试使用本地请求身份，保存服务 request ID（若有），工具 ID 与执行 request/cell ID 显式映射。

模型请求和响应的非敏感有界内容存为独立记录产物，事件使用引用；记录提示词模板版本/哈希、渲染后的实际消息和有效配置。不得记录 HTTP 授权头、环境转储或密钥值；应显式选择可记录字段，而不是仅依靠现有按 key 名脱敏。持久化失败时终止模型请求和容器，禁止新的无记录动作。

输入/输出 token 以 API usage 为依据，缓存命中属于输入明细，推理通常属于输出明细，依据适配器定义归一化并保留原始值。用量缺失保留 unknown；价格未配置时货币成本未计算，不标零。新增模型耗时及尝试次数；运行墙钟包含全部阶段但不能由可重叠字段简单相加。

### 6. 完成结果、导出与代码重放

至少一次成功执行和当前运行的有效证据是 `finish_analysis` 的必要条件；至少一条 finding，methods 描述数据范围、统计口径及必要处理，limitations 可为空列表。数值观察优先使用结构化 value，便于合成任务检查。引用检查只验证存在性、所属运行、已执行状态及产物完整性，不自动证明模型推论正确。

接受完成动作后保存 `analysis.json` 和由其确定性生成的 `analysis.md`，不额外调用模型润色。关闭容器并导出 Notebook，完成记录全部成功才返回 completed；导出或清理失败返回 failed 并保留已接收分析结果。失败、取消和预算耗尽仍尽力导出，不把导出成功转换为分析成功。

沿用现有重放资格：带原始错误、持久化截断或中断的轨迹不支持重放验证，即使智能体随后修复并完成；保留错误单元，不另造“删错版本”冒充原运行。正常单 epoch 轨迹可通过现有 runtime replay 在新容器中执行，模型和 token 为不适用，模型决策不重放。未来全智能体重复运行使用新的 run ID 和单独实验协议，不混同代码重放。

### 7. CLI、验收和提交分段

新增命令形态：`bun run agent run --task <task.json> --models <models.json> --model <profile-id>`。任务文件包含目标、输入根/清单、约束、执行限制和智能体预算；命令行选择优先于任务默认值，所有最终有效值入清单。保留现有 runtime 命令。增加 `bun run test:smoke:model -- --model deepseek-flash --task <synthetic-task>`，入口必须显式给模型和任务且输出生效预算；退出码非零表示任务或验收失败。

验收分层：

1. 快速测试用注入适配器与本地假 HTTP 服务检查配置切换、完整协议、重试、取消、预算、日志及脱敏，不访问真实服务。
2. Docker 集成使用脚本化模型响应驱动真实会话，覆盖跨单元状态、错误修复、非法动作、引用拒绝、预算耗尽和清理；验证旧版记录、导出/重放回归。假响应只用于可控验证，不报告为真实模型成功。
3. 单独 DeepSeek 冒烟使用合成 CSV 和自然语言问题，要求先检查数据、再复用变量计算分组均值、生成图表并提交对应结构化观察。期望 A/B 均值 2/4 仅保存在宿主验收器，不作为任务答案、提示词或执行输入提供给模型。检查至少两个成功单元、已知数值、引用解析、PNG 可解析、Notebook 格式及模型用量；不提供预写分析代码，不把精确单元数量或报告文案作为断言。
4. 冒烟默认运行一个任务，不循环直到成功；失败留档并定位。修复后重跑需记录为新的尝试并累计本次验证成本，不能隐藏失败历史。纯成功轨迹另验证代码重放，带错误修复的轨迹检查如实拒绝重放。

开发按“配置与适配 → 循环与预算 → 记录和 CLI → 集成与冒烟”形成可独立检查的小提交，每段连同相关测试和说明完成后及时提交。

## Risks / Trade-offs

- 模型别名随提供商升级 → 同时记录请求/返回标识、时间和指纹（可获得时），正式比较另外冻结配置与运行时段，不宣称别名能锁定权重。
- 兼容协议存在细节差异 → 以能力声明、适配器和协议测试约束；未验证的配置不等于已支持该供应商全部功能。
- 累计 token 只能请求后准确结算 → 明示停止阈值与未知消费，辅以调用数、时间及输出硬限制；不把估算记为实测费用。
- 完整历史增长和推理字段占用预算 → 有界历史与显式失败，首版不引入可能改变实验语义的自动摘要。
- 正常错误修复后仍不能通过严格代码重放 → 保留原轨迹与现有资格规则，报告分析完成和重放不可验证两个不同状态。
- 真实模型输出不稳定 → 自动化依靠可控测试，真实冒烟只验证必要行为和已知统计，不按一次小样本声称研究收益。

## Migration Plan

先加入版本 1 清单回归夹具与读取兼容，再写版本 2 和模型事件；保留现有 runtime 命令及合成测试。新智能体为独立显式入口，完成默认检查、真实 Docker 集成后再运行已授权的有限 DeepSeek 冒烟。

回退时可继续使用既有 runtime 入口；旧版本程序不承诺读取版本 2 清单，因此保留记录原件并用对应代码版本查看，不降级覆盖文件。密钥、运行记录和本机配置不提交，仓库仅保留不含真实密钥的配置示例、测试和使用说明。
