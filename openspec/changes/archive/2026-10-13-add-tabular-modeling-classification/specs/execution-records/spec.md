# Spec Delta

## ADDED Requirements

### Requirement: 建模任务协议与指标事实

新建模记录 SHALL 保存任务类型、主指标、方向、预测契约、类别映射、正类及数值规则的版本化快照和校验身份，并关联实验、预测、EDA 与最终交付。可信分数 SHALL 包含指标和协议身份，失败/最终拟合实验不伪造内部验证分数。检查入口 MUST 核对实验事实、证据来源、协议一致性和按事件顺序选出的最佳实验，拒绝方向、类别或评分身份不一致的记录。

#### Scenario: 最大化指标的最佳实验
- **WHEN** 用户检查 accuracy 从 0.7 提升到 0.8 的运行
- **THEN** 检查确认 0.8 对应实验为最佳；若最终选择 0.7 且没有合法排除原因，则报告不一致，不沿用 RMSE 的升序比较

#### Scenario: 平局与失败
- **WHEN** 后续成功实验分数与最佳相同，或后续实验无有效分数
- **THEN** 记录保持先前最佳，能够解释平局、失败和最终拟合不参与内部验证排名的原因

#### Scenario: 分类证据协议错位
- **WHEN** EDA 的来源实验相同，但记录中的类别映射、正类或预测校验值与冻结来源不一致
- **THEN** 检查拒绝将该证据报告为有效，不因分析文本提及正确实验 ID 就接受

### Requirement: 表格建模记录的版本兼容

新表格协议 SHALL 显式版本化数据清单、父运行和交付记录；系统 MUST 继续读取、检查、独立复现和离线评分既有合法回归记录，遵循原镜像、输入、划分、RMSE 和容差，不原地迁移或补造类别事实。新格式缺失必需字段或版本未知 MUST 被拒绝，不能按旧回归格式降级解释。独立检查、复现与评分不得改写原运行文件。

#### Scenario: 历史回归交付
- **WHEN** 用户对旧版回归运行执行 inspect、reproduce 或 score
- **THEN** 各入口按原协议工作，兼容视图中的通用指标明确来自原 RMSE，原运行及交付文件哈希不变

#### Scenario: 旧数据用于新运行
- **WHEN** 新程序加载合法旧版回归数据清单启动建模
- **THEN** 保留原输入及精确划分，记录新的运行身份与明确的兼容解释，不覆盖旧数据或重新划分

#### Scenario: 新记录缺失字段
- **WHEN** 新版分类父记录缺失类别映射、协议身份或指标方向，或者记录声明未知版本
- **THEN** 检查及复现拒绝并给出协议错误，不假设 RMSE、默认正类或猜测概率顺序
