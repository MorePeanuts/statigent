# Design

## Context

动机与范围见 [proposal.md](proposal.md)。本变更跨越数据、执行、决策、记录和交付，并涉及历史格式兼容，因此需要设计文档。

现有 `data.ts` 只接受 schema 1 的 regression/rmse，目标必须是有限数值；默认按 seed/ID 哈希作 80/20 留出。`experiments.ts` 将预测解释为一个数值列，内部计算 RMSE。`run.ts`、`candidates.ts` 和 `records.ts` 的最佳选择均依赖 `rmse`。Python runner 将 `predict` 强制转换为浮点数组。`eda.ts` 将真实目标与一个预测列连接；delivery 的分数、复现和独立评分也固定为回归。

已有独立 fit/predict 容器、阶段输入隔离、稳定 ID、候选状态、双角色 EDA、总预算和交付预留可以复用。Python 环境已锁定 numpy、pandas 和 scikit-learn；`evaluation/process.ts` 已提供经过 uv 的有界可信子进程调用。后者是普通进程工具，可复用，不让建模核心依赖任何 Benchmark 适配器。

## Goals / Non-Goals

**Goals:** 以一个冻结协议驱动全部阶段；让新增分类复用现有候选和预算循环；让在线选择、离线 inspect 和交付对指标及类别含义保持一致；保持旧记录只读兼容。

**Non-Goals:** 不把本变更发展成任意指标插件平台，不新增概率校准、阈值优化、采样搜索、分组/时间序列自动划分或交叉验证。训练预算与候选管理保持既有语义。新评分模块服务普通建模任务，不包含基准 ID 或基准参考成绩。

## Decisions

### 1. 用显式任务协议替代各模块中的 RMSE 特例

在 `src/modeling/` 内增加 protocol/predictions/scoring 等职责清楚的模块；名称可在实现时微调。TypeScript 使用有运行时校验的判别联合，核心字段为 `kind`、`metric`、`direction`、`prediction`、`classes`、`positive_class`、`scoring_version` 与 `protocol_sha256`。

| kind | metric | direction | 必需输出 |
| --- | --- | --- | --- |
| regression | rmse | minimize | 原始尺度数值 |
| binary | accuracy | maximize | 原始类别标签 |
| binary | roc_auc | maximize | 全部两类概率及派生标签 |
| binary | log_loss | minimize | 全部两类概率及派生标签 |
| multiclass | accuracy | maximize | 原始类别标签 |
| multiclass | log_loss | minimize | 全部类别概率及派生标签 |

方向及预测类型从这个固定矩阵派生，不能由模型更改。新 `prepare` 输出 dataset schema 2，在现有文件与划分身份之外冻结协议。协议哈希按明确字段顺序的规范 JSON 生成，不包含自身哈希；数据文件与划分继续单独取哈希。跨语言不各自猜测序列化：TS 生成规范内容，Python 校验字段语义并回传请求中的身份，宿主核对。

每次成功内部实验保存 `score:{metric,direction,value,protocol_sha256,scoring_version}`；失败和最终拟合的内部 `score` 为 null。决策上下文使用 `best_validation_score`，完成检查、候选摘要与 inspect 共用同一比较语义。严格优于才替换，完全平局按接受/完成事件顺序保留先前最佳。拒绝不匹配协议、非有限分数及非法分数范围。

替代方案是继续保留 `rmse` 作为通用值并增加分支；它会让 accuracy 最大化和记录审计容易漂移，因此只在历史读取边界保留该字段。

### 2. 将 CSV 标签解释为稳定的字符串身份

分类标签取 CSV 解码后的原始字段字符串，保留前导零、大小写、空格和 Unicode，不做隐式 trim、数值推断或 Unicode 归一化。空字符串和纯空白标签拒绝；非空的 `NA`、`null` 等字面量是合法类别，不采用 pandas 的默认缺失值词表推断标签。回归有限值校验不变。

默认类别顺序按标签 UTF-8 字节排序冻结。二分类配置必须给出 `positive_class` 且恰有两类，多分类至少三类且不接受正类字段；不支持多标签/多目标。将类别依次映射为 0..K-1，runner 以整数类别拟合模型，预测时解码回原标签。这样候选代码仍只需返回兼容 estimator/pipeline，且 sklearn/pandas 无法意外把 `01` 合并为 `1`。

runner 读取目标时使用保留字面值的独立解析，再映射为整数；特征继续使用原读取策略。ID/目标不进入 X。概率列名采用索引而非原始标签，输出描述记录列名到类别映射；与 ID 冲突时确定性追加下划线并冻结名称。EDA 新字段另按其原始数据列避免冲突。

替代方案是直接用 pandas 推断的原标签训练；类型推断会改变用户目标含义，跨语言比较也更脆弱。

### 3. 分类采用确定性分层留出，保留显式划分入口

每类按 SHA-256(seed + ':' + sample_id) 排序，哈希相同以 ID UTF-8 字节排序打破平局；该类验证数量为 `min(n-1,max(1,floor(0.2*n)))`。n<2 拒绝，其余作为训练。记录实际成员、比例和 `stratified-hash-v1`，不承诺小样本时精确 20%。类别顺序和成员排序确定后，输入行重排不改变成员集合。

显式 train/validation ID 列表保留调用者指定成员，验证完整、不相交和每类在两侧均出现；不自动修复无效划分。回归默认算法保持现有规则，旧数据绝不重新划分。无需观察测试标签或统计外层类别频数。

替代方案是随机留出后缺类重抽；它的尝试过程和停止条件难以审计，也会使所有候选的评价基础不明确。

### 4. 在隔离 runner 中提取预测，在可信评分端核算分数

`build_pipeline(seed)` 入口不变。accuracy 调用 `predict` 并校验返回整数类别索引的形状及成员；概率型任务要求 `predict_proba` 和可解析的 `classes_`，后者必须恰好覆盖冻结整数类别，无重复、缺失或未知类别。按 `classes_` 对齐概率列，而非假设模型输出顺序。分类模型元信息随模型保存，以便预测阶段和交付保留协议身份；joblib 仍只在受控容器内加载。

概率必须为 N×K、有限、范围 [0,1]，每行和误差不超过 1e-6。runner 校验后，宿主对产物再次独立校验；不信任候选代码所在进程自报成功。输出包含解码类别和按冻结顺序的概率列；派生标签为 argmax，平局选最小类别索引，宿主核对标签与概率一致。accuracy 不要求支持概率，EDA 对此明确标记不可用。

新增可信 Python 评分入口，例如 `python/statigent_modeling/scoring.py`，通过 `uv run --offline --frozen python -m statigent_modeling.scoring` 调用。它只读取宿主校验后发布的目标/预测快照及协议，不导入 candidate.py、不加载模型、不接受可执行表达式；固定代码计算实际指标。TS 负责身份、调度与协议校验。复用有界进程能力但使用裁剪环境，不注入模型凭据。

请求带协议版本、request_id、协议哈希、允许数据文件及哈希；回复带相同身份、成功 score 或类型化错误。文件输入使用受控普通文件，避免把概率大表嵌入 stdout/提示词；请求/回复限制 1 MiB、stderr 64 KiB，单次评分默认上限 30 秒，搜索评分取该上限与父探索剩余时间的较小值。取消/超时终止进程并计入父墙钟，默认不重试。无效预测是已确认实验失败；评分进程/协议故障终止本次父运行，避免用未知分数选择最佳。独立 score 故障只生成独立错误记录。

评分口径冻结为 `tabular-metrics-v1`：RMSE 为原尺度平方误差均值的平方根；accuracy 为标签完全相同的比例；二分类 ROC AUC 使用显式正类概率，并列按平均秩处理。log-loss 先对已通过概率合法性检查的 float64 工作副本按行归一化，再以 epsilon=1e-15 截到 [epsilon,1-epsilon] 并重新按行归一化，计算真实类别负对数均值；这些仅为固定数值评分规则，不覆盖预测产物、不修复不合法概率。保留公式级小样本期望和锁定 sklearn 的差分测试，涉及裁剪时使用相同预处理和说明。

替代方案是让候选自报指标或在加载其模型的容器中评分；两者均无法维持当前可信评分边界。新版本回归也经过可信评分入口，历史 v1 评分仍保持原数值规则。

### 5. 让 EDA 和模型上下文获得足够的分类语义

建模提示词升级到 `modeling-v3`，根据协议说明模型接口、目标编码、指标方向和所需输出；现有三个动作及候选更新格式不变，预算分配不变。不能继续在工具说明或反馈里无条件出现“RMSE 越低越好”。

EDA 的 `source.json` 加入协议身份、类别映射、正类、预测产物哈希，以及诊断 CSV 中真实标签、预测标签和概率列的映射。按照稳定 ID 连接验证目标和预测。概率型任务发布全部类别概率，accuracy 任务只发布实际存在的标签，不自动补算概率或生成第二个模型。EDA 可以按需分析混淆、类别比例和置信度，不要求固定模板或每轮计算全部诊断。

`AnalysisRecord` 的来源增加 protocol/prediction 身份，`validateEvidence` 与 inspect 一致校验；纯数据 EDA 的来源实验及预测为 null，协议、数据与划分仍明确。跨实验历史证据保持原适用范围和来源，不因为模型更新自动改挂身份。原训练与外层测试访问边界维持不变。

### 6. 版本化交付，保留旧回归读取路径

新父 `modeling.json`、dataset 与 delivery 使用 schema 2；候选扩展仍为 version 1，动作接受协议仍为 2（工具参数未改），提示词版本单独升级。新的协议字段缺失不能回退解释为 v1。stage.json 增加显式协议版本；旧镜像 runner 所需的三字段格式在旧交付复现路径原样保留。

读取层区分 v1/v2，再构造只读内部视图：v1 的 `rmse` 可在视图映射为回归 score，但标明 legacy 来源，不向原文件补写字段。新的运行可以读取旧 dataset，保留其原始快照、划分及哈希，同时在新父记录保存显式回归协议。delivery 继续保存冻结代码、模型、训练/预测入口与镜像，新增协议和分类模型元信息，所有文件纳入完整性检查。

reproduce 的类别逐样本精确比较；概率和回归数值使用交付保存的 atol=1e-8、rtol=1e-6。概率任务还检查派生标签一致性，不能以整体分数相近替代预测一致。refit 同样保留协议及种子，不重演模型决策。现有独立 score 使用冻结主指标，遇到未知标签或 AUC 单类标签返回错误；测试标签依然只供独立评分，不进入搜索。

替代方案是原地迁移旧记录或统一用新镜像重放旧交付；两者会破坏历史证据及冻结环境，故使用版本分派。

### 7. 验收覆盖系统行为，不依赖 Benchmark

快速测试覆盖支持矩阵、错误配置、字面标签保留、分层确定性、类别反序、缺列/错列/非法概率、AUC 正类/并列、log-loss 边界、最大化/最小化及平局、协议篡改与历史读取。Python 评分测试经 uv 执行，现有回归测试继续运行。

真实 Docker 使用可控模型响应，分别完成二分类 ROC AUC、多分类 log-loss 的“初始训练→双角色 EDA→证据关联训练→最佳选择→最终拟合→预测复现→refit→独立评分”；accuracy 的二/多分类另覆盖训练预测与计分路径。检查隔离、类别/概率交接、取消清理及原记录哈希不变。回归整链保留作为兼容回归测试。

提供独立的分类真实模型冒烟入口，可明确选择 binary 或 multiclass；使用各一个冻结小型合成任务，记录生成种子、文件哈希和精确划分，普通配置不强制调用 EDA，协作冒烟才要求完整链路。每次命令仅运行所选一项，沿用当前每项最多 900 秒、40 次总模型尝试、600,000 token、3 次搜索拟合及1次最终拟合、180 秒最终预留，EDA 最多一次且子额度不突破父预算。两项显式运行的最大配置合计为 1,800 秒、80 次尝试和 1,200,000 token 停止阈值；独立复现/评分另列实际耗时。默认检查不运行该入口，真实结果需另外记录，未运行不能标为真实模型已验收。

## Risks / Trade-offs

- [类别很少的样本会使 80/20 偏离较大] → 保存实际成员与比例，少于两例直接拒绝，不静默改类。
- [用户把数值标签当连续目标或反之] → 任务类型必须显式指定，分类保持 CSV 字面值，预检打印类别和正类。
- [概率列带来 K 倍产物开销] → 沿用已有文件/产物/内存上限，超限明确失败；暂不以静默丢列或 top-k 压缩扩大范围。
- [生成代码可以伪造容器内元信息] → 宿主独立校验协议、成员、形状与数值；这保证契约和可信计分，不宣称证明模型概率的统计校准性。
- [版本分派遗漏旧路径] → v1 数据、候选记录、交付、原镜像复现和独立评分都建立回归用例，逐文件校验未被改写。
- [分类模型接口失败或代码修复消耗预算] → 复用现有失败记录及有界修复，不在训练进程安装依赖或额外加跑。

## Migration Plan

1. 先实现并测试协议及版本读取，再扩展执行/评分、建模/EDA、交付链路；相关 Spec、文档和测试与各内聚实现阶段一起提交。
2. 重建带新版 runner 的开发镜像，记录实际镜像身份；历史复现继续要求原镜像，不替换旧镜像标识。锁定依赖无需升级。
3. 新 prepare 默认写 schema 2；旧回归配置仍合法，既有 schema 1 数据保持只读。新示例展示显式 kind/metric/positive_class。
4. 完成快速检查和真实 Docker 功能验收后交付；真实模型冒烟按独立入口显式运行与留档，不能用可控响应结果替代真实模型验收。
5. 回退使用原代码和原镜像继续处理 v1 记录；旧程序遇到 v2 应明确拒绝。保留新记录和原产物，不降级覆盖文件、不重写 Git 历史。
