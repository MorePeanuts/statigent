# Spec Delta

## MODIFIED Requirements

### Requirement: 独立任务会话

系统 SHALL 为每个任务会话分配独立身份、Docker 容器和私有工作空间，支持 persistent-kernel 与 fresh-script 两种后端，缺省保持持久内核。持久后端仅在内核就绪后接收执行；脚本后端仅在受限运行器就绪后接收完整脚本，每次执行另建进程。启动失败 SHALL 返回诊断并清理已创建资源，不得降级到宿主直接执行或其他后端。

#### Scenario: macOS 本地 Docker 启动
- **WHEN** 调用者在 macOS 上配置可用的本地 Docker Linux 容器环境、匹配架构的镜像及有效任务限制
- **THEN** 系统能够启动就绪的执行会话，不要求连接或预先部署到 Linux 服务器

#### Scenario: 两个任务互不共享状态
- **WHEN** 会话 A 已定义变量并创建文件，而会话 B 随后启动
- **THEN** B 无法读取 A 的变量或工作文件，二者具有不同的会话和容器身份

#### Scenario: 启动失败
- **WHEN** Docker 不可用、镜像缺失或内核未在启动时限内就绪
- **THEN** 系统报告启动失败及原因，不执行用户代码，并清理本次已创建资源或明确报告清理失败

#### Scenario: 显式选择脚本会话
- **WHEN** 调用者选择 fresh-script 且镜像支持该后端
- **THEN** 创建任务级隔离容器和工作目录，每次请求使用新的 Python 进程，不创建持久 Jupyter 内核；不支持的后端或协议在启动阶段拒绝并清理，不退回其他后端

### Requirement: 同会话串行执行

系统 SHALL 按接收顺序串行调度同一会话中的代码执行与状态写入，记录实际调度序号，并限制排队容量。持久后端保留跨请求内存，脚本后端仅延续任务文件且须确认前轮执行进程树已结束后再开始下一轮。控制命令 SHALL 能在代码执行期间处理；重复请求 ID MUST 被拒绝，不能重复执行代码。

#### Scenario: 并发提交两次执行
- **WHEN** 一个会话同时收到先写变量的请求和后读变量的请求
- **THEN** 后一个请求在前一个结束后执行，记录的执行序号与实际顺序一致

#### Scenario: 重复或超量提交
- **WHEN** 调用者重复提交已接收的请求 ID，或在队列已满时提交新请求
- **THEN** 系统明确拒绝，不产生额外代码执行

#### Scenario: 脚本串行但不共享变量
- **WHEN** 同一脚本会话排队收到两个请求
- **THEN** 后者在前者结束及进程清理确认后启动，可读取前者的文件但无法读取前者变量，实际顺序保持可查

### Requirement: 超时与取消处理

系统 SHALL 区分单次执行超时、用户取消和普通代码异常。对持久内核活动执行 SHALL 先请求中断，在有限宽限期内确认执行停止及内核可用性；脚本后端 SHALL 在有限宽限期内终止本轮进程树并确认运行器可用性。不能确认时 SHALL 终止任务容器并将会话标为失败。排队请求取消后 MUST 不被执行。

#### Scenario: 可中断的超时执行
- **WHEN** 单元超时，内核在宽限期内响应中断并确认可用
- **THEN** 结果标为超时而非成功，说明部分状态修改可能存在，后续执行仅在确认结束后开始

#### Scenario: 无法确认停止
- **WHEN** 中断后执行仍未在宽限期内确认停止
- **THEN** 系统强制终止容器，标记会话不可用（持久后端同时标明内核不可用），禁止排队代码继续在不确定状态下执行

#### Scenario: 取消排队请求
- **WHEN** 调用者取消一个尚未开始的请求
- **THEN** 请求返回取消且标记未开始，不生成实际执行序号，不产生代码副作用

#### Scenario: 脚本超时后的终态
- **WHEN** 脚本达到执行时限
- **THEN** 有界停止本轮进程树，返回超时及清理结果，说明文件可能部分修改，不把内存不保留报告为内核异常

### Requirement: 状态丢失与显式重启

持久后端 SHALL 在内核退出、连接失效或重启后明确报告状态丢失，不得静默恢复后声称旧变量仍存在或自动重试未知结果的代码。显式重启 SHALL 产生新的内核 epoch，取消旧队列并报告工作文件是否保留。脚本后端的每轮进程退出属于正常状态边界，不构成内核重启；其运行器或容器丢失 SHALL 使会话失效，未知结果不得自动重试，内核重启操作须明确拒绝。

#### Scenario: 显式重启后的变量
- **WHEN** 调用者重启已定义变量的内核并再次读取该变量
- **THEN** 新 epoch 不含旧变量，读取失败如实返回，重启前后记录可以区分

#### Scenario: 执行中失去连接
- **WHEN** 系统无法确认已派发代码的最终结果
- **THEN** 请求被记录为结果未知或内核丢失，会话失效，系统不会自动再次执行该代码

#### Scenario: 脚本正常退出没有内核丢失
- **WHEN** 当前脚本正常结束且运行器与记录完整
- **THEN** 结果表明本轮内存已释放、任务文件保留、会话可继续，不生成虚构的内核重启事件
