# Spec Delta

## Purpose

提供与持久 Notebook 内核可比较的独立脚本执行能力，使智能体在保留任务记忆和显式文件复用的条件下，每轮自行提交完整 Python 程序，并获得可追溯的输出、产物及有界失败反馈，以检验进程内状态持久化与增量执行的影响。

## ADDED Requirements

### Requirement: 每次执行使用独立 Python 进程

`fresh-script` 后端 SHALL 为每次已派发请求启动新的 Python 进程，执行本次提交的完整脚本并记录独立身份。运行器 MUST NOT 在常驻解释器中继续执行、自动拼接历史代码、回放前轮代码或恢复前轮内存。新进程 SHALL 使用冻结依赖、声明的初始化与种子规则；Python 启动必须经 uv。

#### Scenario: 变量不跨轮保留
- **WHEN** 第一轮定义变量，第二轮只读取该变量而未定义或加载它
- **THEN** 第二轮返回变量未定义错误；两轮拥有不同执行进程身份，不因同属一个任务而共享变量

#### Scenario: 完整脚本独立运行
- **WHEN** 第二轮自行导入依赖、读取允许输入并计算统计量
- **THEN** 即使没有第一轮的 Python 内存，第二轮仍可完成并返回真实结果

#### Scenario: 不隐式补全代码
- **WHEN** 当前脚本遗漏先前执行过的导入或前置计算
- **THEN** 运行器只执行当前源码，不为使任务成功而自动补入历史代码

### Requirement: 任务内文件延续与跨任务隔离

同一任务的脚本尝试 SHALL 共享受限工作目录，允许显式读写前轮留下的普通文件，仍仅可读取允许输入。新任务与重放初始工作目录 MUST 为空，不继承其他运行的文件。运行器 MUST NOT 自动恢复对象或复制历史产物作为计算缓存；失败前已写入的文件不隐含回滚。

#### Scenario: 显式复用清洗文件
- **WHEN** 第一轮保存清洗后的 CSV，第二轮显式读取该文件
- **THEN** 第二轮可以使用文件内容，仍需自行建立 Python 对象；记录保留两次实际源码和各自产物快照

#### Scenario: 错误后的文件仍存在
- **WHEN** 脚本先写文件再抛出异常
- **THEN** 返回代码错误，后续脚本可见已写文件，但不能见到失败进程的变量；反馈明确文件可能已部分修改

#### Scenario: 新任务无历史文件
- **WHEN** 相同输入启动另一独立任务
- **THEN** 该任务无法读取前一任务的工作文件、内存、评分材料或宿主凭据

### Requirement: 脚本输出与产物反馈

脚本执行 SHALL 提供可区分的 stdout、stderr、异常、文本与静态富输出，以及显式保存的表格、PNG/JPEG 和报告文件引用。工具反馈 SHALL 有预览和保存限额、完整度及来源身份；图片引用不得声称已被模型视觉观察。执行遵循普通脚本语义，不隐式展示末尾表达式；显式打印、展示和保存能力须在提示中说明，交互输入不得挂起。

#### Scenario: 统计和静态图表交付
- **WHEN** 完整脚本打印统计量、显式展示表格并保存图表
- **THEN** 返回对应文本或富输出和有效文件引用，单角色报告与双角色证据交接均可使用已完整收集的产物

#### Scenario: 裸表达式不产生交互式输出
- **WHEN** 脚本仅以一个非打印表达式结尾
- **THEN** 运行器不自动插入显示语句，也不伪造该表达式的输出

#### Scenario: 输出洪泛或交互输入
- **WHEN** 脚本输出超过保存限制或请求交互输入
- **THEN** 前者有界中止并标记不完整，后者明确报错或 EOF，不无限等待；已收集记录保留

#### Scenario: 标准输出伪装协议
- **WHEN** 生成脚本向 stdout 打印类似控制消息或成功结果的 JSON
- **THEN** 内容只作为脚本输出，不被宿主解释为桥接控制或可信成功终态

### Requirement: 脚本进程树有界结束

运行器 SHALL 在执行结束、超时、取消和关闭时确认本轮进程及其派生进程已结束，再允许后续执行。不得允许跨轮后台服务保留内存或继续写文件、输出。无法确认清理时 MUST 使会话失效并终止容器，不自动重试未知执行。每轮启动、执行、收集及清理消耗 SHALL 计入同一任务时限。

#### Scenario: 脚本退出但子进程仍活动
- **WHEN** 主脚本退出后留下后台子进程
- **THEN** 后台进程被有界终止，确认无残留后才结束本轮并允许下一轮；后续单元不接收其迟到输出

#### Scenario: 无法完成进程清理
- **WHEN** 中断与终止后仍无法确认本轮执行进程树已结束
- **THEN** 会话明确失败并进入容器级清理，后续请求不执行，已有文件状态不被承诺为完整

#### Scenario: 执行期间父任务取消
- **WHEN** 脚本或其子进程正在计算时任务被取消
- **THEN** 停止本轮实际计算、拒绝后续派发并有界清理，不仅取消等待它的客户端

### Requirement: 错误与会话可用性分离

脚本的正常进程退出 SHALL 表示本轮结束，不等于任务会话丢失。普通代码错误在清理已确认、记录完整且预算允许时 SHALL 支持新的完整脚本尝试；异常进程退出、容器退出、协议错误及未知结果须分别诊断，不伪造成功或自动续跑。脚本侧自报成功不得覆盖宿主确认的退出和协议事实。

#### Scenario: 普通错误后提交修订脚本
- **WHEN** 第一轮因代码异常失败并已确认清理，下一轮提交修订后的完整脚本
- **THEN** 使用新进程执行，保留原错误和成本，不依赖失败进程的内存状态

#### Scenario: 正常退出后继续分析
- **WHEN** 第一轮脚本成功退出且任务仍有预算
- **THEN** 会话仍可接受下一完整脚本，反馈明确内存已丢弃而工作目录保留

#### Scenario: 无法确认执行结果
- **WHEN** 容器失联或结果消息缺失且无法可靠确定本轮结果
- **THEN** 标记未知或会话失效，禁止自动重试，不将文件存在当作执行成功证明

### Requirement: 可核对的脚本初始化

脚本后端 SHALL 在每轮以固定规则初始化随机源、工作目录与允许环境，记录任务种子及本轮生效种子。初始化不得引入历史计算结果；初始化失败须阻止用户脚本并明确报告。种子规则 SHALL 在开发对照与重放中保持一致，不将跨进程随机流描述为持久内核中的连续随机流。

#### Scenario: 每轮使用同一任务种子
- **WHEN** 相同任务中两次脚本使用默认种子规则且调用相同随机运算
- **THEN** 各自从记录的同一任务种子开始，记录明确随机状态每轮重置

#### Scenario: 初始化失败
- **WHEN** 新进程无法完成冻结环境或随机源初始化
- **THEN** 本轮明确失败并标明用户代码未开始，不静默以未初始化环境继续执行
