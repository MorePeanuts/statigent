# Proposal

## Why

第一章已经具备单智能体、规划—执行分离及持久 Notebook 内核，但缺少每轮独立 Python 脚本这一执行后端，尚不能检验持久状态与增量执行的研究假设。补齐该后端及四组开发对照配置，使后续预实验能够在相同数据、模型、依赖和预算下比较分析质量、完成率及总成本。

## What Changes

- 新增 `fresh-script` 后端：每次工具调用提交完整脚本，在隔离容器内的新 Python 进程执行；不拼接历史代码、不自动恢复变量，普通错误修复提交新的完整脚本。
- 同一任务保留执行者历史上下文和工作目录，允许显式读取前轮文件；不同任务完全隔离。比较范围是进程内状态与增量执行，不是移除对话记忆或磁盘缓存。
- 复用现有单角色及双角色循环、单动作工具、预算、证据和报告交付，增加后端选择及对应提示。默认继续使用 `persistent-kernel`，保持现有 Notebook 执行和提示词行为，不新增单元编辑、浏览或指定单元重跑工具。
- 为脚本执行补齐身份、输出、进程树清理、脚本导出和按后端重放；旧 Notebook 记录及重放保持兼容，不把脚本进程退出误判为持久内核丢失。
- 新增四组开发对照配置、无模型验收及显式有界真实模型冒烟入口；实际付费冒烟和研究预实验需后续指定范围与预算，本变更不自动开展正式评测。

## Capabilities

### New Capabilities

- `script-execution`: 完整脚本在独立 Python 进程中的执行、文件延续、反馈和进程生命周期。

### Modified Capabilities

- `execution-session`: 会话可选择持久内核或独立脚本，保持任务级隔离、串行派发及累计限制，区分两类后端的可用性与状态丢失。
- `eda-agent`: 两种角色组织均支持后端选择，按后端提供正确的执行与修复语义，保留上下文、证据边界和统一预算。
- `execution-records`: 显式记录后端与脚本执行身份，导出不可变脚本尝试并按原执行语义重放，保留旧记录兼容。
- `agent-adapters`: 透传并校验后端，记录提示词与文件复用策略，支持四组公平开发对照及脚本轨迹交付。

## Impact

主要涉及 `src/execution/`、`python/statigent_runtime/`、`src/agent/`、`src/records/`、EDA 评测适配器与轨迹导出、`configs/evaluations/`，以及对应单元和 Docker 集成测试。Docker 镜像增加固定脚本运行入口，所有 Python 启动继续经 uv，优先复用锁定依赖，不引入新框架。

实施时同步执行、EDA 与评测使用说明，并在研究文档中明确允许任务内文件复用。现有建模流程继续使用原持久后端；本变更不接入建模基准、不增加视觉输入、不修改上游评分、不实现外部论文基线，也不声称完成第一章全部正式实验。
