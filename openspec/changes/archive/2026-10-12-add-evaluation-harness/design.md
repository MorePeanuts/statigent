# Design

## Context

动机见 [proposal.md](proposal.md)。现有 `src/agent/run.ts` 已提供可配置模型、任务预算、取消信号、Docker 执行及原生运行记录；`AgentResult` 返回运行身份、终态、目录和 `analysis`，没有基准专用答案结构。`analysis.summary` 可作为明确的最终回答边界。`src/models/config.ts` 已支持 DeepSeek 和通用兼容接口，无需新建一套模型配置。

现有 `src/records/store.ts` 服务执行会话，schema_version=1/2 清单及代码重放已有语义，不能把任意外部智能体伪装成 Notebook 执行。Docker 传输层也绑定内核桥接协议，不能直接作为任意外部命令启动器。

本地 InfiAgent-DABench 有 257 道公开题、52 份 CSV、独立私有标签和原样保存的上游评分脚本。上游 `evaluate_responses` 跳过缺失及空回答；`docs/benchmark.md` 已要求失败纳入正式统计分母。具体行为契约见本变更的三份 delta specs。

## Goals / Non-Goals

**Goals:**

- 用两个独立适配边界组成评测流程，新增任一侧不要求改另一侧或核心调度。
- 首先跑通本地串行、可核查的开发评测；执行状态、答案指标和成本可信程度分别表达。
- 保持评测与智能体记录分层，保留未来预测文件、报告及不同评分方法的扩展位置。

**Non-Goals:**

- 本次不实现预测建模任务、LLM 评委、联网外部论文智能体、跨基准总榜或自动论文复现。
- 不创建插件市场、动态远程代码加载、分布式队列、数据库、Web UI 或并行调度。
- 不实现未落地的角色组织与后端消融；配置接口只声明实际支持的能力。

## Decisions

### 1. 独立注册基准与智能体，核心运行器只认识公共契约

新增 `src/evaluation/`，分为契约与校验、注册、计划与运行、记录与汇总、`benchmarks/` 和 `agents/`。注册表由受信代码显式装配；配置选择已注册 ID，不能从任务文本或 URL 动态导入代码。适配器是受信工程代码，智能体生成的代码和外部进程输出是非受信输入。

| 边界 | 主要职责 | 不负责 |
| --- | --- | --- |
| Benchmark adapter | 列出任务、校验版本、发布公开输入、提供评分入口及原生指标定义 | 调用模型或组织智能体角色 |
| Agent adapter | 声明能力、接收公开任务、运行与取消、交付答案及成本 | 读取私有标签或实现基准评分 |
| Evaluation runner | 展开计划、预检、串行派发、预算、记录、调用独立评分端、汇总 | 解析特定题号或猜测答案 |

每个批次只对应一个基准版本，可以包含多个智能体配置及重复次数。比较多个基准时分别运行并保留原生指标；后续无需改变智能体契约即可新增基准。相比为每个“基准 × 智能体”编写脚本，这一结构避免重复预算和错误处理；相比独立平台，单仓库模块足以验证复用。

### 2. 统一交付边界，保留内部实现自由

契约使用显式 `schema_version` 并做运行时校验：

- `PublicTask`：稳定任务身份与版本、目标、约束、输入相对路径/大小/校验值、输出契约。输出契约包含类型与公开格式说明；首版支持文本回答，其他类型预检拒绝。
- `AgentInvocation`：评测单元身份、公开任务、具名智能体配置、有效预算、种子和输入发布位置。传给外部命令时只包含容器内路径，不包含宿主基准根或评分路径。
- `AgentSubmission`：匹配的单元身份、终态、`answer_text`、受控产物引用、可选原生运行引用及用量。Notebook 不是必填项；失败诊断与成功交付分开。
- `ScoreResult`：评分身份、任务/交付校验值、协议版本、评分状态、指标及评分侧细节引用。每项指标记录名称、范围和方向，不强行把所有基准转换为一个分数。

能力声明区分可控制、仅可观察和不支持，涵盖模型、种子、输出、隔离与预算。配置中的未知字段及不支持的必需项一律拒绝。模型标识沿用现有 profile，允许相同智能体配置不同模型；外部实现是否支持统一模型由其能力声明决定。

选择“任务进入、最终交付出来”的边界，而不要求所有智能体使用 Statigent 工具协议，以便后续接入保留原有代码结构的论文实现。

### 3. 公开输入发布与私有评分分开

运行器为每个单元创建独立发布区，仅复制允许的普通输入文件，验证规范化路径、真实路径、符号链接、字节数和 SHA-256；拒绝冲突名称及根外引用。每次调用前核验发布文件，模型只接收公开描述，执行容器只读挂载发布区。

私有标签路径、完整基准根和评分器句柄仅在宿主评分侧存在，不进入 agent adapter 的调用对象。原生运行、外部产物和评分详情保存在不同目录；后续单元从原始公开任务重新构建上下文。评分安排在该单元交付冻结并完成资源清理之后，结果不传回智能体。

宿主适配代码和确定性评分程序是受信组件，不把普通子进程称为安全沙箱；实际执行模型生成代码及外部命令仍依靠 Docker 权限边界。

### 4. Statigent 适配保持现有入口兼容

`statigent-eda` adapter 调用现有 `runAgent`，映射公开目标、约束、输入、模型 profile 与预算。仅在适配器生成的任务约束中加入通用要求：“将最终回答按任务要求放入 summary，证据和方法放入其他交付字段”。直接使用 `analysis.summary` 作为 `answer_text`，保留完整 analysis 与 Notebook 引用，不在调试轨迹中用正则猜答案。

适配器读取原生清单与模型请求日志，关联 `run_id`，提取已知用量、未确认请求及清理状态。`runAgent` 可在创建自身记录前抛错，因此评测单元身份和启动意图必须提前落盘。原生 `record_error`、无法确认的模型用量及清理错误不能被包装成普通成功。

首版明确声明只支持当前单智能体与持久内核；未来角色分离通过增加实际实现及能力声明接入。无需在 EDA 核心加入 InfiAgent 字段，也不改变原有直接运行命令。

### 5. 外部命令首版采用离线容器协议

`container-command` adapter 接收受信配置中的固定镜像、argv 数组及资源限制，不通过宿主 shell 拼接命令。记录解析后的镜像 ID；镜像包含智能体依赖。首个测试智能体用 Python 实现，通过 `uv run --frozen python ...` 执行，使用小型合成 CSV 计算回答，证明协议不要求 TypeScript 或 Notebook。

协议为标准输入的一条 JSON 请求和标准输出的一条 JSON 终态响应，stderr 用于有界诊断。请求包含协议版本与单元身份；响应必须匹配身份并通过校验，且进程正常退出，才接受成功交付。额外响应、缺失响应、非法 JSON、超限或非零退出均失败。对 stdout/stderr 流式计数并在超限时终止，不能先无限缓冲再检查。

首版产物通过响应中的有界 base64 内容交付，由宿主校验名称、解码大小并生成路径和哈希；不接受外部命令指定的宿主任意路径。默认请求上限 256 KiB、stdout 总量 8 MiB、stderr 保留上限 1 MiB、单产物解码上限 1 MiB、产物解码总量 4 MiB。上限进入配置快照；这是验证接入的轻量协议，大模型文件的流式交付留待对应基准接入时扩展。

容器沿用现有执行环境的原则：非 root、只读根、只读当前任务输入、临时工作区、无网络、无额外能力、无宿主环境透传、无 Docker socket，设置 CPU/内存/PID 与超时限制。超时与取消按唯一单元标签定位并强制清理实际容器，有界清理失败则停止批次。只复用经过验证的安全配置或小型辅助函数，不强行复用绑定内核协议的 DockerTransport。

本次不向外部容器注入 API key，也不宣称支持联网第三方论文智能体。后续此类适配需明确代理或受控联网、凭据及用量观测方案，再声明相应能力；现在提出但暂不实现不受限宿主命令，避免把协议兼容误认为执行隔离已经成立。

### 6. InfiAgent 保留原生比较语义，显式定义分母

适配器读取现有 `public/questions.jsonl` 与其引用的 `public/tables/`，评分侧读取 `private/labels.jsonl`。版本由本地源文件哈希、`benchmarks/metadata/infi-tree` 及下载清单的来源信息组成，校验固定上游评分文件及许可，不自动下载或改写上游资源。

在 `python/statigent_evaluation/` 实现小型确定性评分模块，以 Python 保持上游正则与浮点转换行为，宿主通过 `uv run` 的有界 JSON 请求/响应调用。接口关联请求 ID，定义成功、协议错误、超时与取消；评分子进程不调用模型，也不执行智能体生成代码。保持上游 `@\w+[值]` 提取、非跨行匹配、重复字段最后一次优先、字符串精确相等或绝对误差严格小于 `1e-6`，不擅自忽略大小写或扩展容差。移植仅限必要纯函数，保留来源及许可说明。

快速测试使用合成标签和答案覆盖边界。独立集成测试对本地未修改的 `eval_closed_form.py` 做差分校验；该文件依赖的 `utils.utils.read_jsonl` 通过测试加载适配补齐，不下载整套智能体实现、不修改上游脚本。此方案比 TypeScript 重新解释 Python 字符串和浮点规则更容易保持一致，也让默认测试无需原始数据。

对每题含 n 个子答案、正确 k 个的有效记录，ABQ 为所有子答案正确时的 1，否则 0；PSAQ 为 k/n。标签必须有非空、唯一、有效的子答案定义，否则是评分错误。终止失败、空回答或缺少答案字段按零分处理；失败状态附带的诊断文本不作为有效最终答案。

主汇总使用每个智能体配置的完整计划单元为分母、每题每次重复等权，保留原始计数和未舍入数值。另存 `upstream_compatible`：仅对有效非空回答计算上游定义的 ABQ/PSAQ（含其四位小数舍入），同时报告回答数、计划数及分母偏离。没有回答时兼容输出沿用上游的 0，但不能省略零覆盖率。未运行、状态未确认或评分错误导致主得分为 null、状态 incomplete；单题已得分仍可查看。不能把这个兼容分数宣称为完整任务成绩或论文复现成绩。

### 7. 串行计划、预算和停止策略

配置包含一个基准版本及显式任务清单、智能体配置列表、重复次数、种子、逐任务预算及整批限制。以任务清单顺序、智能体配置顺序、重复序号稳定展开；冻结计划及其哈希后运行。预检检查所有必需能力、配置、文件、标签结构及镜像可用性；计划预览不要求密钥、不启动容器，执行入口另行检查凭据和运行环境。

运行器持久化单元意图后才启动适配器。一个单元最多启动一次；适配器内部既有模型重试保留并计数。普通任务失败在记录、清理和预算可靠时继续后续单元；用量不确定且影响整批成本约束、关键记录失败或清理失败则停止。取消、整批期限和预算耗尽让剩余单元成为 `not_run`，记录具体原因。

派发前取逐任务与整批剩余额度的最小值，保存实际有效预算；记录被整批限制缩减的单元，不能当成与完整预算完全可比。模型尝试次数在派发前限制；token 为响应结算后的停止阈值，单次响应可能超出阈值，记录真实超额，不能承诺精确账单上限。整批墙钟时间涵盖准备、执行及评分；取消后的有界清理另记实际耗时。

用量由已知小计、未知请求数、测量来源及完整性共同表示。Statigent 请求日志提供可追溯的模型返回用量；外部返回仅属自报告；确定无模型调用的离线测试智能体标记不适用。无模型调用与缺少遥测不同。货币成本默认 `not_computed`，不维护价格表；评分耗时单列，当前确定性评分没有模型成本。

### 8. 独立、可检查的文件记录与离线评分

在被 Git 忽略的 `runs/evaluations/<evaluation_id>/` 保存新的评测 schema_version=1：`manifest.json`、冻结计划、追加事件、逐单元交付与状态、原生运行引用、`scores/<score_id>/` 以及 JSON/CSV 报告。原生 Statigent 运行继续使用原有记录器。各目录及文件都有明确容量限制，事件引用大对象，不内嵌完整轨迹。

快照记录源码 commit/dirty、适配器和评分协议版本、完整脱敏配置、公开与私有数据版本、任务清单、模型请求名与展示名、提示词版本、种子、锁文件哈希、Bun/Python/Docker 及硬件信息；不可获得的信息明确为 unknown。记录先写临时文件再原子替换；关键意图和事件在派发前持久化。凭据只记录环境变量名，配置与日志禁止真实 key。

状态分开存储 `execution_status`、`scoring_status`、`budget_status` 和 `usage_completeness`。CSV 每行对应单元，包含分组键与指标；JSON 保留完整语义。汇总同时显示计划数、启动数、终止数、评分覆盖率、失败率、用量及耗时；不同基准/数据/评分协议/配置分别分组。成本不完整或控制条件不同必须标记，不能静默排除失败单元。

`inspect` 只读，不自动恢复异常退出留下的单元。`score` 校验已保存交付与数据后生成新 score_id，原评分和原生记录不变，缺失执行仍保留，不触发模型。定向 `cleanup` 仅处理指定评测身份拥有的遗留容器，记录操作，不自动重跑任务。相比自动恢复，显式检查和清理可避免崩溃后重复付费及错误继承状态。

### 9. 入口、开发集合和分层验收

新增 `bun run evaluate`，提供 `plan --config`、`run --config`、`inspect <id>`、`score <id>`、`cleanup <id>`。不传子命令仅显示帮助；配置文件或环境存在密钥不代表自动执行。模型仍引用 `configs/models.json` 的现有 profile。

在 `configs/evaluations/` 冻结 12 题开发清单，每个公开难度 4 题，同一 CSV 最多 2 题；按任务 ID 排序，依据公开题目、概念和现有镜像依赖选择无需新增训练依赖的题目。记录公开的纳入/排除依据及文件哈希，选择过程不能读取答案或参考成绩。若无法满足规则则明确报错并修订清单版本，不能运行后按分数换题。开发用过的题目与 CSV 关系被记录，后续正式集合显式处理重叠。

真实冒烟配置固定取清单中各难度首题，共 3 题、1 个 Statigent 配置、1 次重复。使用现有 DeepSeek profile（请求模型 `deepseek-flash`，展示名沿用 profile），默认单题最多 12 次模型尝试、100,000 token 停止阈值、300 秒；整批最多 36 次尝试、300,000 token、1,200 秒，清理另有上限。预算与配置都落盘；若任务答案错误如实记录，不通过提高分数或追加重试作为软件验收条件。

验收分三层：默认 `bun run check` 用合成数据与可控模型；独立集成入口验证真实 Docker 外部命令、隔离、取消及本地上游评分差分；显式真实冒烟验证 3 题从发布到 JSON/CSV 的完整记录。两个合成 benchmark adapter 与两个可控 agent adapter 的组合测试证明扩展边界；Statigent 与外部命令各有真实执行链路测试。不把无模型测试智能体的合成成绩当成真实基准表现。

## Risks / Trade-offs

- 首版只有一个真实基准 → 使用第二个合成基准验证核心不含 InfiAgent 分支；开放式报告与预测文件仍需未来真实适配验证，不能声称已支持。
- 外部命令首版离线且产物有限 → 明确能力拒绝及大小限制；联网论文智能体和大文件交付作为后续变更，避免虚假的通用性承诺。
- 上游忽略缺失回答 → 主分母遵循本项目研究约定，兼容输出明确单列；差分测试只比较约定相同的部分。
- Token 遥测不完整或外部自报告不可信 → 保留来源与未知数，必要时停止批次；成本完整性独立于答案分数。
- 公开 validation 集已用于开发 → 记录开发题与共享 CSV，正式实验冻结新清单并披露关系，不按开发成绩选择任务。
- 真实模型输出不稳定 → 验收执行、记录与评分链路，准确率只作为实际结果；重复实验由明确的新配置发起。

## Migration Plan

增量加入评测模块及独立命令，原有 runtime/agent 命令、执行记录和重放保持兼容，无数据迁移。先完成合成契约测试，再接真实 Docker 和本地评分资源，冻结开发清单后显式跑真实冒烟。按可独立验收的实现阶段提交。

回退时停止活动批次并清理其专属容器，停用新增入口即可继续使用原 EDA。保留评测目录及旧分数用于审计，不迁移或覆盖既有运行产物。
