# Design

## Context

动机与范围见 proposal.md；研究依据为 `docs/overview.md` 第二章，数据约定见 `docs/benchmark.md` 和 `benchmarks/README.md`。

已核对的实现：

- `src/agent/run.ts` 提供完整单角色/双角色 EDA、独立 run ID、持久会话和取消信号；`AgentResult` 当前未直接返回总用量，评测适配器从原生记录中取得用量。
- `src/agent/model-call.ts` 已处理模型协议、重试与预算，但接口绑定 EDA 元数据；新增建模循环需要小范围解耦调用能力，不能复制一套易漂移的实现。
- `src/execution/`、`python/statigent_runtime/` 已提供受限 Docker 会话与文件快照。现有默认单文件产物上限 512 KiB，不适合作为所有模型文件的隐含上限，建模配置须明确资源和收集上限。
- 统一评测只声明 text/report 输出，当前基准注册覆盖分析任务；本变更通过独立建模入口交付，不将模型塞进报告契约。
- Python 环境没有 scikit-learn。DSBench 建模数据已下载，但未接入训练与评分。公开任务 `playground-series-s3e9` 指定目标 Strength、指标 RMSE，训练文件约 217 KiB、测试特征约 48 KiB；本次未读取私有标签或测量训练成本。

此变更横跨执行、记录、模型调用及数据隔离，需要显式设计。现有 EDA 验收只证明一次协作成功，不能假定嵌套调用后成本已足够低。

## Goals / Non-Goals

**Goals:**

- 以单目标回归完成一条可复核的端到端纵向路径，保持决策、实验执行、分析与评分的模块边界。
- 复用现有完整 EDA；建模智能体负责实验选择，普通程序负责运行、校验和计账。
- 让固定评价协议、证据来源、失败记录和交付预留在首版即可验收。

**Non-Goals:**

- 本次仅支持 RMSE 回归、单个固定内部留出划分和 CPU 训练；不设计通用 AutoML 平台。
- 不引入新的训练规划者/执行者双角色、搜索树或智能预算调度器。
- 不证明 EDA 的因果收益，不将内层自适应验证分数表述为泛化成绩，不承诺抵御模型有意把已见标签硬编码到代码中的所有语义作弊。

## Decisions

### 1. 独立建模循环，三个有界动作

新增 `src/modeling/`，入口采用 `bun run modeling` 下的 prepare/run/inspect/reproduce/score 子命令。核心运行接收通用回归任务，不知道 DSBench 编号。配置保留建模和 EDA profile 字段，首版验收固定同一 profile；EDA 使用现有 planner-executor 组织。

模型动作：

- `run_experiment`：候选 ID、假设与改动、依据/直接试验理由、可选来源实验、有效证据引用、流水线源代码。
- `analyze`：少量候选及优先级、待调查问题、所需证据、各结果对决策的影响、来源实验或纯数据范围。
- `finish_modeling`：引用宿主认可的最佳实验和选择说明，触发已冻结方案的最终训练与预测。

候选与实验身份分离：一个候选可以修复后产生新实验，失败尝试不覆盖。结构化字段只要求可追溯，不增加判定“分析是否够好”的模型裁判。模型一次只能提交一个动作；数量、长度、代码、产物及引用均做运行时校验。候选和历史有配置上限，超过限制明确停止，不悄悄丢弃证据。

选用单一建模决策智能体，以免在第二章重复第一章角色设计。沿用第一章适中粒度原则；不把固定训练顺序写成生产算法。合成测试可脚本化模型响应以覆盖完整路径，真实模型仍自主生成代码与分析内容。

### 2. 冻结数据协议，分阶段发布输入

通用任务包含允许训练表、无标签预测表、目标列、稳定行 ID、指标与方向、种子、内部划分清单及内容哈希。默认开发内部划分为训练部分的 80/20 固定随机留出，准备时保存精确成员，后续不重新抽样；显式已有划分优先，首版拒绝时间/分组协议等未支持设置。目标、ID、列模式、行数及文件校验值在调用前检查。数据目标不合法时失败，不自动删行改变问题。

按阶段创建独立允许清单：

| 阶段 | 允许输入 | 不发布 |
| --- | --- | --- |
| 候选拟合 | 内部训练特征与标签、候选代码及配置 | 验证特征/标签、外层测试数据 |
| 验证预测 | 保存模型、内部验证特征 | 验证标签、其他训练状态 |
| 内部评分 | 冻结验证标签和已校验预测 | 不执行生成代码或加载模型 |
| EDA | 允许训练数据、内部划分身份、指定实验的验证预测 | 外层测试特征/标签、私有评分资源、其他运行 |
| 最终拟合 | 全部允许训练数据、冻结候选代码 | 外层测试特征/标签 |
| 最终预测 | 最终模型、无标签外层测试特征 | 测试标签、评分反馈 |

建模 LLM 接收字段说明、协议、指标和分析反馈，不自动塞入整张表。缺失模式与误差调查通过 EDA 获得。样本 ID 与目标列由宿主剥离后传给流水线，避免标识符被意外当特征；首版不支持未经声明的多表连接。

内部验证标签可用于 EDA 诊断，这是有记录的自适应验证使用；拟合阶段的数据隔离由独立挂载执行。该安排无法证明 LLM 不会根据已见验证信息过拟合，因此外层标签和反馈始终独立，所有收益结论留给后续正式实验。

### 3. 智能体生成流水线，宿主控制 fit/predict 与评分

新增 Python 建模模块，约定生成代码导出 `build_pipeline(seed)`，返回兼容 fit/predict 的回归流水线。模型自行选择可用预处理和估计器；宿主包装器加载代码，调用 fit、保存流水线，在另一个新容器中加载并 predict。目标变换必须包含在流水线中并逆变换输出，不能在评分前更换目标尺度。

每次拟合和预测复用现有 DockerSession 隔离能力，但使用新的容器和空工作空间，不共享前一个实验内核。阶段之间仅传递宿主已保存并验 hash 的代码/模型快照；候选验证路径不开放任意输入位置。启动、执行、收集及清理均计入该实验耗时。没有必要为首版新增另一套跨语言传输协议。

训练结果不是任意 JSON 自报分数。验证预测由固定包装器绑定样本 ID，宿主用有界 CSV/结构校验后交由可信评分实现计算 RMSE。评分环境不导入生成模块或反序列化模型。进程成功但预测、模型或收集不完整仍为实验失败。

锁定 scikit-learn 与必要的 scipy/joblib 依赖，通过 uv 更新声明和锁文件；Python 均经 uv 运行。允许使用镜像内的 CPU 模型，不允许运行时安装包。复用已有模型服务调用、Docker 安全配置与文件收集，小范围抽取通用部分并覆盖 EDA 兼容测试。采用生成流水线而非固定几个模型模板，以保留自主建模；采用宿主控制执行阶段而非一段任意脚本自报所有结果，以固定评价口径。

### 4. EDA 是带数据版本的独立子运行

建模宿主先保存调用意图与 `analysis_request_id`，再把允许文件复制到专用发布区。误差分析快照按稳定 ID 连接验证特征、目标和预测，并绑定 `experiment_id`、数据/划分哈希；拒绝缺失或不匹配。模型工具参数只能引用宿主登记的身份，不能指定任意宿主路径。

调用 `runAgent`，指定双角色、子额度和父取消信号。一次子运行内部仍共享 Notebook；不同调用的新会话只读显式快照，不承诺复用以前 EDA 内存。回传 analysis、有效证据、来源信息、终态及可信用量摘要，不回传内部代码、错误栈与完整模型历史。首版采用结构化文本结果，不要求 EDA 每次写 Markdown 报告。

完整 EDA 只有接受的最终分析可进入有效证据集合；失败、部分工作或无分析返回只作诊断，建模智能体可选择直接试验或另发有界分析。子运行的已知失败可反馈父智能体，但未知模型消费、记录不完整或父预算终止属于全任务终止条件。

### 5. 串行分配子额度，父总账只结算一次

父预算包含总模型尝试/token/墙钟、训练尝试、EDA 调用/执行次数、修复/动作纠正次数和产物上限。每次派发先检查总剩余和交付预留。EDA 获得 `min(请求子上限, 父探索剩余)` 的额度，父循环等待其返回，不并行派发其他操作。使用现有 EDA 内部预算限制活动调用；结束后按可信摘要以子调用 ID 幂等结算，不能再把角色小计加一次。

对现有模型调用做必要的通用上下文提取，继续共用请求/用量验证和有界重试；新增父预算协调器负责跨运行分配。EDA 返回用量可以增加向后兼容摘要接口，或从校验过的原生记录读取，选择更小改动路径；无论采用哪种方式，必须覆盖子运行失败、记录读取失败及未知用量。子运行身份在第一次外部副作用之前与父意图关联，不能仅在成功返回时登记。

开发冒烟初始上限：总 40 次模型尝试、600,000 token 停止阈值、900 秒；最多 3 次搜索拟合及 1 次最终拟合、1 次 EDA 调用/10 次 EDA 执行；单次拟合 120 秒、单次预测 30 秒。EDA 子上限为 20 次模型尝试、400,000 token、300 秒，并继续受父剩余限制。为最终拟合/预测/收集保留 1 次拟合与 180 秒，同时在请求中明确应及时选择 finish；不承诺到达硬上限后还能追加 LLM 完成动作。资源采用 1 CPU、2 GiB 内存，工作空间与产物上限显式配置并在实施预检中校验。

这些是首版开发上限而非性能承诺。实现可先通过无模型训练预检校准文件/工作空间限制，首次真实调用前将最终生效配置提交冻结；更改额度需记录为新配置，不能失败后自动加预算重跑。生产接口不把 EDA 次数硬编码为 1，普通配置可在父预算内设置其他有限上限。

普通代码错误产生新实验；最终交付重试也必须计数、受预留限制。最终阶段只能处理执行层可恢复故障并重试已冻结代码，不能变更模型方案后绕过验证。候选代码未知执行结果不自动重试；如需新的模型方案须回到有预算的搜索和验证阶段。

### 6. 最佳模型与交付冻结

可信 RMSE 决定最佳有效实验，平局保留先完成者。finish 必须引用当前最佳；宿主冻结该实验的代码/配置，在全部允许训练数据上重新拟合，然后发布测试特征用于预测。最终拟合不产生可与内部验证成绩混排的新分数。

交付目录包含流水线源码、模型、训练/预测入口、依赖与镜像身份、输入/划分版本、配置、种子、验证指标来源及预测 CSV。生成代码和 pickle/joblib 模型均仅在沙箱加载。最终拟合或收集失败时保留先前最佳实验并明确未完整交付，不悄悄退回内部训练子集模型。

独立 reproduce 在新容器加载保存模型并预测，按固定 `atol=1e-8, rtol=1e-6` 比较有限输出、样本身份和列结构，保存新记录并验证原产物哈希未变。训练入口可重新 fit 已选方案；首版功能验收主要验证预测复现，不把它称为整个搜索/训练轨迹复现。

### 7. 建模记录独立扩展，保持 EDA 格式兼容

父运行使用版本化建模清单与追加事件，复用现有安全文件/哈希及事件写入机制，不强行将父运行伪装为 Notebook。记录候选、训练阶段、EDA 请求、分析前后的优先级和理由、有效证据范围、最终交付、预算分配与结算。EDA 与各执行阶段继续保存原生记录，通过身份与相对引用关联。

模型、预测等大文件独立保存并设明确大小上限；父清单不嵌入大对象。旧 EDA 记录不原地升级；新增 inspect 理解父子结构。总墙钟与各阶段耗时分列，父子成本不相加两次。记录失败停止新副作用。

### 8. 小型开发准备与分层验收

先用小型合成回归夹具与可控模型响应，覆盖至少两次候选训练、真实双角色 EDA、证据驱动的后续选择、最终拟合及独立预测复现。增加“改进变差仍保留原最佳”“直接训练不调用 EDA”“失效证据/恶意路径/预测错误”“子运行取消/未知用量/重复结算”等分支。EDA 内部沿用已有跨委派状态测试。

真实开发固定为 `playground-series-s3e9`：以公开目标/指标、文件小且已下载为选择理由，首个真实调用前提交输入哈希、来源版本、精确内部划分及预算。准备器把已有 DSBench 公开 train/test 转成通用契约，不下载补充原数据，不按照模型成绩换题。原题面路径和提交示例行数以本地文件及清单为准。该薄准备器不宣称支持整套 DSBench 或官方 RPG 聚合。

私有标签只由独立 score 入口在交付冻结后读取，校验身份后计算原生 RMSE；不将评分喂回搜索，也不使用它挑题、加跑或挑配置。默认测试和 plan/prepare 不调用付费模型。

实施末尾在快速与 Docker 检查通过、代码/配置已提交后进行一次固定开发任务的有界真实模型验收。模型必须真实经历训练 → 定向 EDA → 关联证据的后续训练 → 交付，不能通过宿主预写分析或放宽验收器补足。未走通如实记失败，不自动追加真实运行；不要求后续模型分数上升。冻结交付的离线评分与预测复现不调用 LLM，独立留档。

## Risks / Trade-offs

- [双角色 EDA 成本可能占据总预算] → 固定子上限、父额度和交付预留，保留真实消耗；本轮不引入自适应分配算法掩盖问题。
- [多阶段容器启动增加时间] → 复用现有镜像与执行实现，分列启动/训练/预测耗时；以隔离和可比较性换取首版额外启动开销。
- [分析后多次使用同一验证集导致过拟合] → 标记自适应使用，外层测试只作冻结后的独立评价，不从一次开发分数推导研究收益。
- [生成代码或序列化模型可执行任意逻辑] → 仅在已有 Docker 权限边界内运行；宿主可信评分不加载模型，文件交接拒绝越界与链接。结构隔离不等于代码语义正确性证明。
- [大模型文件超过 EDA 默认收集限制] → 为建模预检显式模型大小/总产物上限，超限失败，不截断后继续交付。
- [单任务回归验收覆盖有限] → 只声明回归闭环成立；分类、更多指标、两套主基准完整适配及正式实验另开变更。

## Migration Plan

1. 先新增任务/记录与无模型训练能力及依赖锁，再接建模循环和完整 EDA，不改变既有入口默认行为。
2. 补充 `docs/modeling.md`、开发配置和验收记录，保持主规格、实现与测试一致。真实调用前提交生效代码与配置。
3. 现有 EDA 快速/集成测试继续通过；新建模失败不能影响旧运行检查、导出和重放。
4. 若回退，停用新增建模入口并回退对应提交即可；运行目录保留且由其版本解释，不迁移或删除历史数据。无需外部服务或数据库迁移。
