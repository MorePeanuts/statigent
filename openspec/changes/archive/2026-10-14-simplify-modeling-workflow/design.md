# Design

## Context

动机和范围见 [proposal.md](proposal.md)。当前 `run.ts` 将候选、认识、动作、资源共同接受；`budget.ts` 的统一检查会在未知 token 时抛出停止，`finalize.ts` 又使用同一检查。结果是分析失败不仅结束搜索，也使已有可信模型无法进入原本不需要 LLM 的确认与交付。

现有隔离训练、可信评分、终局确认和独立预测复现可复用。`experiments.ts` 已有 fit/predict 分阶段执行；Python stage 3 可以用保存模型预测另一份无目标特征输入，无须新建训练框架。`development.ts` 当前还为完整协同追加固定动作目标，不能用于观察自然建模行为。

本地三组轨迹的关键依据如下；完整路径见提案，原始数据和轨迹不提交 Git。

| 运行 | 可核查事实 | 本次处理 |
| --- | --- | --- |
| collaborative `90118d10…` | 父事件 14、19 将 finding 句柄放入原始执行引用；已有两个有效搜索实验。第二次 EDA 请求训练/验证诊断却缺少训练预测；子运行末次规划请求失败且用量未知，最终无交付 | 统一句柄、直接提供诊断、未知用量停止 LLM 后安全收尾 |
| adaptive_eda `e57fd347…` | 事件 36、52、68 把初始探索的空模型来源改为后来的模型身份；最终交付和独立预测复现通过 | 宿主绑定原来源，不让模型重复填写身份 |
| no_eda `dd27d19b…` | 事件 18 虚构分析引用；事件 89 第八次搜索受拟合预留限制被拒；事件 94 完成动作暂缓不存在的 c8，再次被拒；修正后交付通过 | 附加引用非阻断、取消候选事务、可关闭总拟合次数限制 |

这些观察支持修复具体协议与流程问题，不足以判定哪种方法预测更优。末次 EDA 请求只有 `transport_or_protocol_failure` 和未知用量证据，不能断言余额不足或某一种供应商故障。

## Goals / Non-Goals

**Goals:**

- 决策模型主要处理“分析什么、训练什么、为何改动、何时结束”，宿主管理身份、证据绑定、资源及交付。
- 正常路径保持一个串行决策循环；明确完成与受保护停止共用现有确定性收尾函数。
- 用可控回归证明恢复边界，用少量自然目标真实运行检查是否实际减少流程阻塞。

**Non-Goals:**

- 不增加调度器、自动语义裁判、异常后的新 LLM 角色或自动恢复未知请求。
- 不改变第一章 EDA 的角色与结束协议，不把执行者完成子任务当成 EDA 已完成；失败 EDA 的诊断文本不能成为成功 finding。
- 不更改终局确认的短名单、两次划分、排序和任一失败即确认不完整的规则；不把搜索模型当作完整交付兜底。
- 不以这一整包修改证明某单个机制的收益；轻量 EDA、历史压缩、进一步移除保护及正式消融另立后续实验。

## Decisions

### 1. 一个最小动作接口，附加说明单独处理

新版工具形状如下，字段细节由运行时 schema 保证；不增加另一套语义判断模型。

| 工具 | 核心字段 | 宿主负责 |
| --- | --- | --- |
| `analyze` | `question`，可选 `source_experiments`（零至两个） | 按来源数确定探索、诊断、对比；核对成功搜索实验及共同评价身份 |
| `run_experiment` | `code`、`change`、`reason`，可选 `source_experiment`、`repair_of_experiment` | 生成实验 ID，核对本任务已确认来源；修复对象必须是已确认失败搜索实验 |
| `finish_modeling` | `reason` | 检查是否有可信搜索模型，自行按冻结协议选取短名单 |

工具名称在新的决策协议中固定，不要求模型提交 candidate ID、候选清单、优先级、暂缓状态、预期证据或最佳模型 ID。`source_experiment` 表示方案沿用的已确认实验，不赋予加载旧模型或改变输入权限；`repair_of_experiment` 表示代码修复，并非统计解释被否定。

所有方法可附加 `sources: [{source_id, applicability?}]`；仅 collaborative 可附加 `notes: {text, sources?}`。核心 JSON、工具数量、权限、执行输入及实验关系仍严格检查。核心合法后逐项核验 sources，整份核验 notes，输出接受结果和附加警告，再持久记录后派发。无效来源不进入有效依据；非法笔记整份忽略并保留旧版本；其他方法提交笔记警告并忽略。核心被拒时不发布任何附加更新。

未知字段不获得执行语义；已知可选字段类型错误按附加警告处理，必需核心字段错误拒绝。整个响应不可解析或多工具响应仍拒绝。记录写入失败禁止派发。附加说明不是另一项必须完成的动作，也不消耗核心纠错次数。

替代方案是继续为每个旧字段添加提示和自动修补。真实轨迹显示重复身份本身就是误差来源，因此删除重复字段；不会把错误内容静默修成有效证据。

### 2. 宿主实验历史与一份可选笔记

新运行从真实接受训练生成实验历史，保存代码哈希、改动理由、父实验、修复对象、阶段、结果和耗时。没有派发的想法只是笔记，不生成“等待执行候选”，也不需要在结束时逐个关闭状态。

协同笔记采用替换快照：省略保留，空文本清空；宿主生成递增版本，记录关联动作和原文。初版上限为文本 8 KiB UTF-8、每份附加来源集合最多 16 项；超限不截断或阻断动作，给出警告。版本用于事件审计，不要求模型提供基版本或处理并发修订。任务内串行接受，无跨任务共享。

统一来源目录继续使用简短句柄：`profile:/...`、`analysis:<analysis-id>:<finding-id>`、`experiment:<id>:score`、`experiment:<id>:failure`，增加明确标为训练诊断的 `experiment:<id>:train_diagnostic`。宿主只发布真实可用句柄，绑定原数据、划分、模型、预测及完整证据身份。模型只说明适用性，无须填写原始 execution/cell ID。探索分析没有模型来源时始终为空，不能随着后续训练改写。

四组共享普通任务、分析报告、实验历史和真实反馈；只有 collaborative 增加上述笔记及 EDA 笔记交接。将已有报告保留在普通历史中，不为制造消融差异刻意清空其他组上下文。此处不新增历史压缩策略。

替代方案是完全删除认识载体。保留可选笔记能以较小接口成本支持“认识影响实验、反馈修正认识”；是否产生额外研究收益仍需后续对照，不能从笔记条数推断。

### 3. 停止新增模型调用与停止所有执行分开

在 `budget.ts` 和父循环中分离模型请求资格、搜索执行资格、收尾执行资格，复用现有账本。未知用量仍明确记录，不估算为完整账目，也不继续新增 LLM。

| 触发情况 | 后续模型请求 | 后续执行 |
| --- | --- | --- |
| 已确认普通训练/EDA 失败，资源尚可 | 可继续，返回真实诊断 | 可按下一合法动作执行 |
| 核心格式/来源错误 | 有界纠正 | 不派发错误动作 |
| 附加笔记/来源错误 | 正常继续 | 核心合法即可执行 |
| 模型额度耗尽、用量未知、连续无进展、探索时间进入收尾预留 | 停止或直接结束搜索，不请求模型补写完成 | 通过收尾资格检查时进入确定性收尾 |
| 取消、总时限到达、持久记录失败、数据/产物完整性异常、执行或清理未确认 | 停止 | 停止新执行，有界清理并保存已有产物 |

EDA 普通失败只有在执行、记录与清理已确认时可恢复。子 EDA 的用量未知仍依既有规则终止；父任务结算后可以关闭搜索并收尾。其部分诊断可作为失败反馈，但不包装成已完成分析或有效 finding。初始 EDA 失败且无可信搜索模型时没有收尾资格，按实际故障结束或在普通可恢复故障下继续建模。

连续无进展沿用有界保护：核心拒绝、确认的失败执行、不可派发请求累计；成功 EDA 或有效搜索分数重置；附加警告不累计。达到上限停止搜索。新策略版本应与旧累计/连续策略明确区分，不追溯改变旧运行结果。

安全收尾须同时具备：可信搜索最佳及完整产物、已结算并确认清理的子运行、可写记录、未取消且未到总时限、足够确认及最终拟合执行资源。资格不满足就保存已完成产物和原因。收尾阶段仍逐步检查剩余墙钟和执行资源，不能因开始时有预留就忽略后续超时。

替代方案包括对未知 token 进行上界估算后继续 LLM，以及故障后新建恢复智能体。两者增加账本与重试复杂度；本次采用较小改动，先确保已有可靠模型有机会交付。

### 4. 同一确定性收尾入口与三个独立结果维度

接受 `finish_modeling` 或宿主保护触发后，以唯一冻结事件进入 `finalize.ts`，停止搜索，只执行现有确认、全训练拟合和预测；同次运行不得重复启动这一流程，也不跨进程自动恢复未知执行。保护原因由宿主生成，不能伪造一条模型完成动作。

新父记录分别保存：

- `search_end`：`agent_finished`、`protected`、`failed` 或 `cancelled`，以及准确原因。
- `delivery`：`not_started`、`running`、`completed`、`failed` 或 `cancelled`，关联真实产物和选择依据。
- 现有成本完整性及未知调用：继续独立表示，不因交付成功改成完整。

最终根状态只有交付及必要清理、记录均成功才可为 completed；它不是“自主搜索成功”的替代字段。保护交付可以通过交付和预测复现检查，轨迹仍标为非自主完成、保留故障。确认不完整时不跳过、不按部分均值排名；搜索模型只列为可保留产物。`inspect`、开发报告和 `reproduce` 均检查这些关系。

替代方案是放宽成功定义、直接返回搜索模型。这会掩盖未完成最终训练与确认，本次不采用。

### 5. 用现有预测阶段提供训练诊断

搜索顺序为 fit → 验证 predict → 可信验证评分 → 同一保存模型的训练 predict → 可信训练评分。训练预测输入去除目标，精确使用该次 fit 的训练成员；生成代码仍在受限容器执行，评分端读取标签，宿主不反序列化模型。优先确认验证结果，辅助训练诊断不增加一次 fit。

诊断保存 `partition`、精确成员身份、任务/模型/预测身份、指标及状态，反馈训练和验证表现与耗时。训练诊断失败但执行与清理已确认时，记录 unavailable 和原因，保留有效验证资格；执行、清理或完整性异常按全局故障规则处理。确认与最终拟合不增加此辅助阶段。

EDA 清单发布训练与验证诊断的独立表及字段说明。不可用诊断显式说明，不让 EDA 寻找模型目录。所有预测沿用分类映射/概率和稳定样本身份检查；训练分数不参与排名，也不当作额外验证。辅助预测和评分实际耗时计入父任务，不隐藏成本。

替代方案是让 EDA 自行加载模型预测。这扩大输入和模型加载边界，也重复计算；沿用宿主已有协议更直接。

### 6. 独立的新开发资源配置

新增 `configs/modeling/resources/workflow-dev-v1.json`，不修改 `collaboration-dev-v1`。新任务允许 `training_attempts: null` 表示关闭总拟合次数上限；省略、零、负数不能表达无限。有限次数仍保持最大确认和最终拟合预留预检，null 时仍逐次记录实际拟合数。

新配置沿用已核查的 45 分钟、80 次模型请求、120 万 token、单次 fit 120 秒、predict 30 秒、750 秒收尾预留、一次最终拟合，以及既有 EDA 三次调用/30 次执行和单次 20 请求/40 万 token/300 秒。关闭总拟合次数限制，保留其他保护以集中检查这次协议变化；不据此宣称已找到最优资源方案。真实硬总时限仍覆盖收尾。

提示只展示与当前可用动作有关的资源与剩余时间，避免继承的通用执行计数被误解为建模搜索上限。没有剩余 LLM 额度不等于没有剩余执行资源。该配置只用于开发，不冻结正式实验条件。

### 7. 显式版本与旧运行兼容

新任务 schema 3；父运行、动作及交付 schema 4；决策接口 `modeling-decision-v2`，提示新版本，笔记独立版本 1。保留 Python stage 3 和已冻结评价协议。版本分流集中在解析/读取边界，旧候选和类型化认识只保留旧格式读取与审计所需代码，不让新循环继续维护双套状态。

旧 schema 1/2/3 的 inspect、reproduce、score 保持原语义与输入哈希，不原地迁移；新格式缺字段不能降级猜测。旧任务启动须显式迁移到新任务，数据清单可读取并在新运行保存计划。四种方法名称保持，但记录版本、提示及能力差异，不能将历史 collaborative 与新版视为相同处理。更新 `methods.json` 及示例时注明新配置；历史资源和运行不重写。

### 8. 以具体轨迹回归和交付为开发验收

| 层次 | 范围 | 通过依据 |
| --- | --- | --- |
| 可控响应单元测试 | finding 句柄错误、探索来源误填、无 EDA 的虚构引用、资源拒绝后直接完成、非法笔记及修复关系 | 合法核心继续，非法核心拒绝，错误证据不认证，无虚构候选 |
| 故障回归 | EDA 已执行并清理后最后规划调用用量未知；无 LLM 额度；无最佳模型；取消/截止/未知执行/记录失败 | 正例无新增 LLM 地进入原收尾；负例不启动新拟合；未知成本完整保留 |
| 真实隔离执行集成 | 合成回归与分类、训练诊断、笔记交接、确认及独立预测复现 | 同模型/正确分区、无标签越权、可信指标、事件及快照一致，确认失败仍未交付 |
| 少量真实模型运行 | s3e9 的 collaborative 与 no_eda 各一次，相同新资源、seed 42、deepseek-flash 与确认协议 | 分别核验产物和独立预测复现，检查轨迹；不按 RMSE 优劣或固定 EDA 次数验收 |

真实运行在相关检查及完整集成通过、代码已提交且配置已冻结后执行；每组最多一次，不自动重跑或换题。沿用原开发任务和输入划分，不读外层测试标签。运行报告列核心拒绝、附加警告、重复无进展、实际分析—实验关联、结束触发、确认/交付及独立预测复现；人工依据轨迹判断是否有卡住现象，不新增在线裁判模型。

若 collaborative 自然未使用 EDA，交付可通过，真实协同链记未覆盖，可控链路另列；若靠保护交付，记受保护通过而非自主完成。两个用例不足以证明总体可靠性或机制收益。若仍失败，保留失败链和待修问题，不自动追加付费运行制造成功。历史归档未通过项维持原记录，新结果单独链接。

## Risks / Trade-offs

- [简短笔记可能遗漏或误述事实] → 保留原始实验/分析记录和可信来源；笔记明确是模型判断，排名和交付不依赖其陈述。
- [忽略附加错误可能掩盖接口问题] → 保留逐项警告并在开发轨迹中统计，不将“动作执行成功”当作“证据正确”。
- [保护交付掩盖搜索失败] → search_end、delivery、accounting 分列；真实自主完成与保护交付分开汇报。
- [训练诊断增加耗时或失败面] → 复用同一模型、不增加拟合，验证优先，普通辅助失败不废弃已有有效模型，实际成本完整记录。
- [关闭拟合次数限制后可能长时间搜索] → 保留有限总时限、模型请求及单步保护，按预留触发收尾；不把次数无限误作任务无限。
- [多版本读取扩大维护面] → 兼容代码限定在边界与小型历史夹具，不维护旧版在线建模循环。
- [一揽子修复无法分离机制收益] → 本次只声称工程行为与用例交付结果；后续机制实验独立冻结条件。

## Migration Plan

1. 在当前任务分支按协议/记录、核心循环、诊断、验收几个内聚阶段实现并通过相关检查后提交。先加入旧格式夹具，确保迁移过程不损坏历史检查和复现。
2. 新入口显式要求 task schema 3；示例和方法配置切换新版，旧资源配置保持原样。更新研究大纲中的实现形式及消融边界，不宣称研究收益已证实。
3. 运行默认检查与隔离集成，通过后冻结代码和两次真实运行清单；记录失败不删改、真实验证不混入默认 CI。
4. 保存单独开发验收报告，区分已实现、已通过可控检查、真实交付和未覆盖能力。规格同步、归档、推送/合并按相应后续工作流和授权进行。
5. 需要回退时采用正常回退提交恢复旧启动行为；保留所有新旧运行和版本标识。旧程序不得尝试读取 schema 4 为旧格式，检查新版记录仍使用对应新版工具或提交快照，不原地降级文件。
