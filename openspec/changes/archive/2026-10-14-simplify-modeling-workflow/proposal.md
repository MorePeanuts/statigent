# Proposal

## Why

三组 s3e9 真实轨迹暴露了重复证据填错、候选事务阻断完成，以及 EDA 用量未知使已有有效模型无法交付的问题。当前阶段优先验证智能体能否顺畅推进、从局部故障恢复并可靠交付；微小 RMSE 差异不作为本变更的成立依据。

## What Changes

- **BREAKING**：新建模动作只表达分析问题、训练代码与改动理由、完成理由及必要实验引用；取消模型维护的候选创建/优先级/暂缓事务。宿主从真实动作和实验生成历史与关系，完成时自行选择可信最佳。
- **BREAKING**：完整协同的类型化认识状态改为可选简短笔记；统一来源句柄并由宿主绑定身份。无效的附加笔记/引用单独报告，不阻断本身合法的训练或完成，不将无效引用认证为证据。
- 分离搜索结束原因、交付状态和记账完整性：已确认的普通 EDA 失败可以反馈后继续；用量未知停止新增 LLM 请求，但在执行、记录、清理均可确认且有可信最佳时进入无 LLM 收尾。取消、真实总时限、记录或执行完整性故障仍停止新执行。
- 搜索实验提供宿主核算的训练与验证指标、对应预测引用及耗时；EDA 能直接获得被允许的诊断输入，不需要寻找未发布模型。训练指标只用于诊断，不能参与最佳排名。
- **BREAKING**：新启动与记录协议显式版本化，旧 schema 1/2/3 运行仍可只读检查和按原协议复现。新增开发资源配置可关闭总训练次数上限，以全局时限、单次执行限制和连续无进展作为保护，保留收尾时间。
- 开发入口使用自然建模目标，按轨迹、正常/受保护收尾与独立预测复现验收。固定协同路径和故障注入放在可控测试，真实模型不强制两次 EDA、笔记数量或分数改善。

本次不改第一章 EDA 的角色组织，不新增分析角色、语义裁判或预算调度算法，不改终局确认排序/失败规则，不接入新基准，不开展正式性能实验。轻量 EDA、历史压缩及单机制收益对照另行开展。

## Capabilities

### New Capabilities

无；复用现有能力边界。

### Modified Capabilities

- `modeling-agent`：最小动作、宿主管理实验关系、附加信息非阻断、局部恢复和无 LLM 收尾。
- `modeling-knowledge`：可选笔记、统一引用、宿主版本与跨轮交接，取代类型/状态机及共同事务。
- `modeling-experiments`：训练侧诊断预测与可信指标、搜索停止后的冻结收尾和已有产物保留。
- `modeling-method-variants`：新版四种方法的笔记边界、自然目标开发验收及宽松保护配置。
- `execution-records`：新版决策/笔记/实验关系、搜索与交付分列、未知记账和历史 schema 3 兼容。

## Impact

主要涉及 `src/modeling/{actions,decision,candidates,knowledge,prompt,run,budget,config,eda,experiments,finalize,delivery,records,preflight,development,smoke}.ts` 及相邻测试。复用受限预测阶段和独立评分程序，原则上不改变 Python runner stage 3，不新增依赖；具体诊断产物由 TypeScript 编排生成。

同步 `docs/overview.md`、`docs/modeling.md`、开发验收记录和建模配置；旧资源文件与历史失败记录保持原样。现行候选/认识原子提交及未知用量停止父任务的规范需要显式替换，不能只靠提示词绕过。
